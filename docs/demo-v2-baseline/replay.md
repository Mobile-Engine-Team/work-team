## 启动一次全新的复验

前提为同机已按恢复文档解出 11/19 副本，并有原版两份源码、离线 node_modules、冻结 PostgreSQL 工具和可用的本地 54329 实例。需要 Python 3.11+。启动器查找恢复材料中的 `MW-V2-Local-*.app`，也可通过 `WORKBENCH_V2_ELECTRON` 指定归档内的 Electron 可执行文件。从研究仓根目录运行以下命令。在独立终端保留它，等到输出本轮数据库名，看见两个标题分别含 V2 Baseline A、B 的原生窗口。

```sh
python3 products/dsh-team-workbench/docs/demo-v2-baseline/replay/desktop.py
```

启动器为每轮创建新数据库、上传副本和两个空资料目录，校验版本、恢复指纹和 API build。端口已占用时先识别占用方再选择空闲测试时间。终端按回车会结束本轮两窗、UI 和 API，保留本轮工作目录和数据库。先从“成员与智能体”停掉自己启用的执行端。真实退出某一窗再打开的测试应保持另一窗和 API 运行；复用同一个资料目录与模型端配置，不能再跑一次新库启动当成冷启。可从启动器终端按提示单独重开 A 或 B。

## 时序、故障与差异的判读

- 先校准初始屏幕、当前工作区、角色、端的在线状态，再逐行执行。窗口截图同时留“动作前”和“稳定后”；提交中、失联、恢复、取消、焦点变化各取独立记录。按 Tab/Shift+Tab 观察焦点环，按 Enter、Esc 后记落点，用通知/旧评论链接时核对聚焦对象。截图不表达的状态见[实测树](evidence/observations.json)。
- WS-11/12 可在**该轮唯一的新库**用独立 psql 会话执行 `BEGIN; LOCK TABLE public.workspace IN SHARE MODE;`。窗口点创建，观察按钮和 Esc，再在同一 SQL 会话 `COMMIT;`。第二次用另一个 slug、快速双击后解锁并数行。受控锁只延缓写入。另一实验用调试协议转发/延迟 HTTP 响应得到 201/409 且留原处，仅作实验条件冲突记录。
- FL-01 和 COMMON-02 用隔离客户端拦截单一路径。先只令 `POST /api/upload-file` 失败，选小文件，验证两种表单的重试与 Esc，移除故障后复验。再只令测试 API 的 GET 失败，改搜索触发新查询，等待超过 10 秒；恢复读请求再触发在线/聚焦，提示消退。其余请求保持畅通；保留失败端与另一窗作对照。
- 业务编号允许映射，日期、UUID、主机名与模型正文允许自然变化；同一条数据必须始终映射到同一对象。逐项比较归属、授权、状态变迁、可见动作、时间先后、计数、链接目的地和返回位置。异步加载和实际完成另记时间。图文一致但 B 看错对象或产生额外执行，仍按差异登记。
- 差异单记录“基线编号｜两端版本及条件｜原版证据｜迁移侧证据｜可见差别和业务影响｜待用户裁决”。没有原版结果的子条件先补证。涉及真实模型额度、外部 SSH、实际凭据或有历史影响的归档操作，按第 06 章列出的条件单独取证。

## 边界样本的重放

- **翻页与候选。** A 另建团队“分页复验”（baseline-pages），通过 UI 新建一件“分页种子”。运行 `python3 products/dsh-team-workbench/docs/demo-v2-baseline/replay/fixtures.py --pages 本轮数据库名` 安装[分页数据](replay/pages.sql)，或手工增加分页样本-001 至分页样本-101 共 101 件待规划任务。返回列表刷新，按默认排序翻页，分别数 50、50、2 行。另建“分页候选项目”→施工蓝图→编辑草案→加入已有任务；空搜索先列至多 100 条。找出一条未出现的标题，键入后应能搜到。冻结原版用带 q 的新请求，不能将它和话题的固定候选集混同。
- **多人蓝图冲突。** A、B 同在“交接演练”，都编辑同一草案和节点“核对交付”。B 将交付要求改为“B 的冲突选择稿”，暂缓 B 发出的 PUT /api/projects/{projectId}/blueprint/draft；A 随即在同一字段写“A 的远端已保存稿”，待 A 保存成功后放行 B 的原请求。核对弹窗的两个单选、Esc、按钮状态。选自己的稿合并，待自动保存后从 A 重新读取草案。可用隔离窗调试协议的 Fetch 拦截来固定保存先后；只延缓上述请求，保留原请求、响应和 revision。
- **附件与私有深链。** 在 B 打开 baseline.txt，点击弹窗中的“下载”，将本轮下载目标设为单独目录。应得到同名 UTF-8 文件，SHA-256 为 `9618d564da4a860e707fafbd6a203490ff9f970a753c4f6b07dd900389a18251`。再把 A 当前私有回答的含 conversation 地址放进 B 的同源窗口；B 保留自己的身份，检查正文、侧栏、错误和输入栏四处。
