## 2026-11-26 用户裁决

**测试起点可以任选。** 可以先尝试带入旧用户数据，让两套产品从同一现场开始比对。如果兼容成本高，可以跳过相应旧状态，直接用新账号按[复验步骤](replay.md)重建相同角色、任务和附件。下面 D-03～D-06 说明采用旧现场时如何判断带入正确。无论选哪种起点，在相同条件下都按冻结基线及已批准的例外核对实际操作、权限和结果。

| 编号 | 用户决定 | 后续怎样判断 |
|---|---|---|
| <a id="d-01"></a>D-01 首次启动 | 已确认。所有用户共用一个通用 macOS .app。双击即到达冻结版恢复启动器打开的业务入口，空资料先显示登录页。注册、登录和数据访问按账号区分，本地目录如何组织由实现决定。 | 验收两种场景。① 同一台 Mac、同一份客户端资料：A 写下私有草稿，退出并登录 B，B 看不到 A 的草稿或私人视图，仍能访问已授权的团队任务。② 同一 .app 以两份隔离测试资料同时打开 A/B，双方可协作。分别给账号打包、仅用两个目录互相隔离，均不足以通过第一种场景。 |
| <a id="d-02"></a>D-02 登录与定位 | 已同意。沿用已有身份切换时允许重新登录一次，进入个人工作区。 | 原账号可在选择器找到原团队并保有原角色。另选新账号复验时，通过加入测试团队重建对应角色。 |
| <a id="d-03"></a>D-03 已有对象及链接 | 可尝试迁入。迁入时保留用户可见编号、内容、归属、权限和引用关系，允许内部 ID 改变。 | 旧通知能定位原评论，结论所承接任务能追溯采用版本。A 的私人对话和固定视图仅 A 可见。 |
| <a id="d-04"></a>D-04 草稿与偏好 | 可尝试带入原版还能找回的内容，包括工作台未发送问句、已保存的结论草稿和切换前存在的蓝图恢复稿。窗口位置、缩放、列表筛选和看板视图允许首次重设。 | 按用户、工作区与会话比对。普通新任务及评论草稿仍按原版关闭或刷新后的表现验收。 |
| <a id="d-05"></a>D-05 附件与未读 | 可尝试带入。已绑定附件按字节、版本顺序、来源评论核对。未发送的临时文件允许重选。 | 逐账号核对已读、未读和归档，同时核对红点事件数和聚合卡片数。用新账号也可通过两次同名交付和跨成员通知重建此场景。 |
| <a id="d-06"></a>D-06 执行与凭据 | 尝试接续时保留助手、共享授权和端绑定，旧凭据确实不能沿用时再认证。未领取任务确认旧端不会再领取后可接续；已领取则优先由原端完成并回写。 | 接续状态无法确认时显示“已中断，可手动重试”。禁止静默重跑或重复扣费。也可从新账号、新建助手和新任务开始测试。 |
| <a id="d-07"></a>D-07 两项交互变更 | 已同意，两种测试起点均适用。任务列表点“重置”后清除筛选并留在任务页。新建任务上传附件失败后，允许重试、移除失败项或取消弹窗。 | 对照 [TL-03](03-任务与协作.md#tl-03) 和 [FL-01](03-任务与协作.md#fl-01) 的原版记录。工作区表单残留、共享助手类型显示、通知按任务聚合等继续按原样验收。 |
