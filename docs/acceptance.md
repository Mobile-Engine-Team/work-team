# 首批迁移验收

2026-11-25，macOS 本机。产品分支 `codex/dsh-first-batch` 从 `bd08af3` 开始。源版本用 [详设](design.md#基线与阅读入口) 固定，`scripts/prepare-multica.sh` 校验三个 HEAD 后从 Multica 的 Git 对象导出源码到产品资料目录。副本的 API 主监听使用回环地址，关闭固定 6060 的调试监听。数据库从空集群执行冻版迁移，迁移完成至 630。

## macOS 客户端和 V2 界面对照

在 macOS 26.0.1 启动 A、B 两个实际 `.app`。AppKit 窗口使用各自持久化的 WKWebView 数据资料，启动对应的本机 DSH Host，再加载 DSH 插件装配的工作台。默认打开命令指向应用包，浏览器保留为开发和回归入口。关闭 B 端 Host 后重新打开 B 客户端，确认客户端能自行启动 Host 并显示登录页。

|界面|迁移及桌面复验|
|---|---|
|登录与注册|复用冻版 V2 的背景、品牌标识、插画、玻璃卡和装饰，恢复右侧账号密码表单、注册确认密码及登录切换。A、B 分别注册，显示各自账号和个人工作区。|
|工作区壳|沿用 V2 的工作台顶栏、空间选择器、创建和退出位置、224 px 能力侧栏、未读计数和底部账号区。A 建团队，B 在自己的窗口接受并进入同一个团队。|
|任务|按 V2 排列创建弹窗、列表与看板切换、搜索、筛选和四列任务表格。详情保留状态及负责人控件、任务要求和协作记录，右侧列出任务产物及输入材料。桌面 A 创建并分派任务、写评论，再从详情分派给验证智能体并回读完成结果。|
|收件箱|沿用 V2 的标题、通知正文、未读标记、右侧操作和折叠历史。B 的桌面窗口收到 A 的评论通知，打开后焦点进入对应评论。|
|智能体小队|沿用 V2 的空状态、卡片栅格、负责人和成员计数、成员／指令双栏。桌面创建小队并设置负责人，⌘R 后回到同一个小队详情。|
|成员与智能体|沿用 V2 的成员、执行端及智能体三区布局和我的／团队智能体页签。桌面回读双方角色、启动实测执行端、保存绑定的智能体，验收后从同一窗口停止该执行端。|

登录素材来自 `dbf36f4d2a9b69779c18cb5fec22ce3ee6302a69` 的 `apps/app/public/`，保留 [上游许可](../packages/ui-workspace-shell/assets/LICENSE.upstream)。图标复用同机 V2 的 `apps/desktop/resources/icons/icon.icns`。V2 界面参考以实际冻版渲染、源组件与样式为准。在 1240 × 800 下对照登录、任务列表与新建弹窗、任务详情、收件箱、小队和成员页。两套渲染使用新工作台的测试数据。干净副本通过离线锁文件安装、前端构建、类型检查和两个应用包的生成。

独立项目页面、工作台对话和固定视图沿用首批设计的后续范围。任务附件本批支持已关联文件的列表和产物评论定位。上传、预览、下载、产物版本历史和智能体起草仍待迁移。桌面执行验收使用本机确定性执行器。

## A1–A8 浏览器实测

`pnpm test:browser` 用 Chrome 的两个独立 context 和实际 DSH Host。账号、团队、任务、评论、小队、绑定和回执都存入独立 Multica。浏览器通过产品入口写入，受保护业务读接口用于交叉核对。项目是测试通过冻版 Multica API 创建的前置数据，任务表单从产品 Host 查询并选择它。

|用例|结果|核验记录|
|---|---|---|
|A1|通过|无 DSH 本机连接凭据的 API 请求为 401。完成 DSH 授权而尚无工作台会话时也为 401。两端注册并各有一个个人空间，刷新恢复会话，退出立即拒绝后续数据请求，错误密码有提示，正确密码可重登。|
|A2|通过|创建表单拦截非法团队标识，接受带短横线的合法标识。A 顶栏创建空团队并获 owner。B 接受邀请前无法读取团队，接受后为 member。刷新保留团队选择，个人空间不显示邀请动作，直接请求个人空间邀请也被服务端拒绝。|
|A3|通过|新建带状态、B 负责人、项目、截止日期、优先级的任务，编辑标题和状态。搜索加项目和状态筛选，切看板。A 发两条真实成员提及，B 回读同一任务及两个不同评论 ID。经冻版 API 关联的输入附件可在任务侧栏回读。个人空间读取该任务被拒绝。|
|A4|通过|B 逐条切换已读未读，归档后依据任务组恢复。展开同一任务的更早通知，两条各自跳到自己的评论并聚焦，刷新仍定位，返回收件箱有效。不存在的评论显示错误并可返回。|
|A5|通过|成员页回读真实登记 runtime，创建并编辑绑定的 Agent。小队设置该 Agent 为负责人，添加 B 并编辑角色，编辑小队名称和指令后重新打开。B 回读负责人和角色，直接改小队被服务端拒绝。|
|A6|通过|成员页启停真实 Multica daemon，从任务页显式派工，观察 `running` 到 `completed`，产品页显示 `WORKBENCH_FIXTURE_OK`。回读的 run 使用同一个 runtime 且有开始与结束时间。停止、重启后 Agent 绑定保持。|
|A7|通过|A 端禁用 bridge 后执行控制路由返回 404，已登记执行端、Agent 和邀请仍可见。用仅含可发布文件的独立 pnpm 装配物安装新 DSH profile，省去收件箱包及装配项。启用后无收件箱入口，旧收件箱 URL 回落到当前空间的任务页，小队仍可打开。恢复默认组合后两项入口恢复。|
|A8|通过|停掉独立 API 后任务页显示错误，恢复后读到原记录。主动推进测试会话过期后显示登录页，受保护读取返回 401。延迟前一空间的真实响应，切到个人后旧数据未出现。同一表单连续触发提交只生成一次请求和一条任务。补测真实写入后的响应丢失，保留表单内容并先刷新匹配记录。|

A6 的上游组件是实际 Multica API、PostgreSQL、登记与派工服务、daemon、Codex 协议适配器和回执通路。进程内执行器为 [本机确定性 fixture](../scripts/fixture-codex)，只使用 stdio，返回固定文本。daemon 探测路径锁定该 fixture，其他 CLI 路径显式禁用。桌面实测在同一任务页回读完成回执，运行前缀为 `01a2111f`。最终浏览器全量回归的运行前缀为 `01a21123`，runtime 前缀为 `b9504ba1`。真实模型、生成质量和真实模型账户登录没有执行结果。

## 配置与接口证据

|记录|方式与结果|
|---|---|
|冻结与隔离|脚本检查 V2 Client、Multica、DSH 三份固定 HEAD。PostgreSQL 54339、API 18995、DSH A 18996 和 B 18997 都绑定 127.0.0.1。原 V2 UI 13887 和 API 18966 验收前后均返回 200，对应监听进程未变。|
|DSH 组合|A、B 各持久保存 `workbench` profile。官方 base 和 web-app 后安装本产品 bundle。用 DSH 的合成配置核对默认七个装配项、禁用 bridge 标志和移除收件箱后的六个装配项。实际浏览器由优先级较高的产品 root 接管，保留官方 renderer 和 web 连接。侧栏来源是已注册的 keyed 页面 slot。|
|Client 构建|从各包 JSX 构建单文件 Browser Module Loader 产物，React 由 DSH 提供。各 UI 从壳公开契约接收用户、工作区和导航，任务与收件箱没有组件互相引用。|
|Host 传输|冻版 DSH 的 `scripts/generate-typert.ts` 从含 `tsconfig.host.json` 和 `packages/` 的上游工作区分析 Host 聚合入口。已安装 CLI 可解析 app-boot，却无法解析 Typert generator。首批使用固定版 DSH `connection.fetch.register` 的受保护准确路径，避免依赖上游 Host/Client 联合生成。业务请求先过 DSH 本机 owner Peer 鉴权，再做工作台会话、请求来源和固定操作校验，由 Multica 执行空间和角色鉴权。|
|身份资料|DSH 本机链接在每端私有启动文件中，工作台浏览器持 HttpOnly 会话 cookie，JWT 只存在对应 Host 的私有会话文件。daemon 单独使用真实 Multica PAT 和独立 HOME、CLI profile、工作目录及 UUID，停止时撤销 PAT。CLI 进程身份和目标 profile 一起核对。|
|构建与契约|`pnpm build` 构建全部 Client。 `pnpm check:types` 检查可导出的页面与目标契约。 `pnpm test` 的四项测试覆盖请求路径与字段边界、受保护 handler 校验、会话隔离与权限、确定性执行器协议。由本产品 Git 导出的干净副本通过离线锁文件安装、构建、类型检查和四项测试。|
|持久化与真实浏览器|`pnpm test:browser` 逐项输出 A1–A8。实际浏览器请求使用临时生成账号，报告仅记录结果及脱敏 run/runtime 前缀。产品启动文件、签名资料和浏览器授权不入库。|

## DSH 装配复盘

|需求|预计影响|实际影响与验证|
|---|---|---|
|给任务列表加「按项目筛选」|现有任务查询已有项目 ID 时只修改任务页|本批 Host 已公开项目目录和任务过滤字段。选择器、条件、视图和清空行为在 `ui-tasks`，没有变更页面 Slot 或跨页目标。由于新数据库最初无项目，复验用 Multica API 增加测试项目，浏览器选择后交叉核验任务的 `project_id`。|
|从通知直接打开指定评论|壳加跨页目标，收件箱和任务两端联调|实际涉及 `ui-workspace-shell` 的 URL 目标与切换保护，`ui-inbox` 的单事件 ID，`ui-tasks` 的定位/聚焦/回退。Multica 归档按整组操作并返回有限代表，复验先恢复组再点不同评论。没有跨插件导入页面实现。|

首次装配额外成本是读固定版连接授权与浏览器模块格式、单独构建 Client、管理独立 profile 和验证插件开关。产品连接路由使用原有 DSH 工具，DSH 核心源码无需改动。
