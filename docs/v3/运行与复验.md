# MobileWork V3 运行与复验

## 本机启动

macOS 首次安装沿用仓库的部署器。它从冻结的 Multica 源码构建 Go API、迁移器和 CLI，加载 DSH Host 与 React 插件。首次启动数据库时执行基础迁移和 V3 增量。浏览器或 Electron 均经 DSH Host 访问同一用户所在的工作区。

```sh
brew install node@24 go postgresql@18 pgvector
scripts/deploy setup
scripts/deploy open
```

要使用自己的模型，在终端运行 `scripts/deploy model` 后重启 API。模型凭据属于本机私有运行资料。自建智能体的外部执行需要在账户菜单的运行时页面启用相应设备、绑定执行端和配置该供应商。正式 Work 默认使用服务端模型配置，未配置的调用会显示不可用或失败。定向邀请通过站内账号收取。密码账号沿用目标仓库的本机账号命名空间，邀请时填写成员资料显示的完整地址（用户名加 `@demo.mobilework.invalid`）。后端保存 bcrypt 密码哈希，签发登录会话，按账号收件箱送达。部署器以 production 模式显式启用本机密码认证。测试没有发送外部邮件。

在左上角「创建团队」得到只有本人和内置 Work 的团队。「新建演示工作区」会在数据库事务内生成新的成员、项目、任务、草案、会话、小队及文件，每份样例使用独立 UUID。新样例通过工作区计数器分配手册中的展示编号 ANDR-101 至 ANDR-111。ANDR-110 对应归档样例，下一项手动创建的任务从 ANDR-112 开始。样例成员用于展示归属。多人登录测试通过真实注册和邀请建立独立身份。

## 项目任务、草案同步与发布

1. 创建空项目，从「任务 → 查看可推进任务」核对无正式版本提示。选「前往施工蓝图」，创建草案、加入两个节点，从上游的「连接下游任务」开始，再聚焦下游节点按 Enter 完成依赖。也可在选择下游前取消连线。
2. 预览发布并关闭，回项目任务页核对真实任务数。再次打开预览，确认发布 V1 后刷新任务页。通知负责人和请求智能体执行各有单独的确认入口。
3. 再次编辑草案。用第二个账号在全部任务修改已有任务的截止日期，第一个账号在草案修改标题或位置。点「同步任务最新内容」并确认，核对标题、位置、依赖和新截止日期。两个账号同时修改同一标题会返回冲突。处理冲突后可以重新同步，再预览并确认 V2。
4. V1 发布后，在新草案里添加下游节点并连接，等到显示「已保存」。选中下游节点修改交付要求，立即按上游的连线按钮，再打开「版本历史 → 查看此版」。V1 仅显示当时的节点和依赖，选中节点后标题为只读；返回当前计划并刷新，核对草案的交付要求和已保存的连线。另可在独立样例把 V1 的一项任务移到别的项目，删除另一项，再回看旧图。两项均保留快照标题；原项目的推进列表排除这两个 ID。
5. 在「体验调研 → 施工蓝图 → 编辑草案」打开「加入已有任务」。分别用标题和部分任务编号搜索，验证本项目及未归属的任务可见、其他项目的任务不可见。按 Esc 退出再打开，核对画布没有新增节点。将画布平移后纳入一项未归属任务，核对该节点已选中并回到视野。同一草案再次搜索时，该任务应从候选消失。看到「已保存」后刷新，在全部任务核对归属仍为空。发布 V1 后，用原编号打开任务核对项目归属。可运行[跨页候选回放](../../tests/v3/blueprint-candidates.mjs)复现 101 条同前缀任务的场景。
6. [服务集成](../../tests/v3/service.mjs)比对失败前后的数据库版本及任务数量。[客户端回放](../../tests/v3/blueprint-refresh.mjs)在服务器真实写入与客户端收到回执之间延迟传输，验证继续编辑、自动保存和刷新恢复。

在施工蓝图里拖动一个节点，保持按下时检查连线跟随预览；系统取消操作后应回到原位。松手后等到「已保存」，再撤销并刷新，应读回原布局。单击一个节点，再按住 Shift 点击另一个节点可同时选择两项，再点一次移出选区。点画布空白处清除节点和右侧检查器。用 Tab 聚焦一条依赖线，按 Enter 或空格打开「下游需要什么」。多选节点后打开「用 AI 调整蓝图 → 查看本次发送的输入」，可核对选区；改为选中连线时，原节点选区清空。[画布手势回放](../../tests/v3/blueprint-gestures.mjs)分别读取拖动中、取消后、提交和撤销后的真实服务端草案。

## 多人会话和附件

在当前会话输入文字后刷新，原账号在同一标签页可继续编辑草稿。发送成功后草稿清空。如果服务已保存但客户端丢失回执，保留原文字、重新发送会复用同一请求。附件仅保存在发送页面，刷新后需要重新选择原文件。

每条消息可发送四个附件，单个上限 3 MB。一个消息请求在同一数据库事务保存正文、文件及发送结果。迁移 656 保留既有文件的下载 ID，多文件按选择顺序展示。「我的文件」中的每个文件都有自己的 ID，点击来源定位同一条原消息。服务会在列出文件和下载时分别核对会话参与资格。

迁移 657 记录发送时选中的智能体 ID。在输入框下点击「智能体」，只能选当前身份在该会话可调用的对象。选中后若其权限有变，服务在发送时重新检查。已保存消息的重试会返回原回执。

会话右上角可查看参与成员、搜索本会话或打开临时 Work。会话设置可复制链接。所有者可编辑会话名称、关联项目及群成员。名称在输入停顿、失焦或回车时自动保存，中文输入法组字期间保留本地草稿。所属项目在选中时保存。每次修改使用上次服务回执中的版本，服务会拒绝其他窗口提交的过期修改。迁移 660 为群聊保存智能体成员。升级前的群保留原有真人名单，智能体名单从空集合开始。新建演示团队的交付协作群有三位真人、内置 Work 和交付整理助手。会话所有者可从当前有权调用的智能体和自己的 Work 助手中邀请，点击邀请即写入。移除须二次确认，可在确认前取消。刷新后可核对名单。加入名单不会派发工作，点名时服务仍按发起人身份核对调用权。参与者可从设置里的「将讨论整理为任务」填写任务标题和描述，保存前可取消。

## 智能体归档与小队交接

迁移 658 将归档、业务任务变更及逐条活动记录绑定到同一次提交。归档智能体时，未完成业务任务改为已取消，正在等待或运行的队列项同步取消。恢复入口在「智能体 → 已归档」中，恢复对象后可以重新指派新工作。原来已完成或已取消的工作保留原负责人、状态和历史。

在「智能体」详情归档在任队长，会列出受影响的小队。逐一打开小队并更换队长后，再返回归档。归档小队前可以核对当前队长。在确认时，未完成任务交给此时的队长。从旧版升级时，如果小队原有的队长已归档且仍有待转交工作，整笔操作返回冲突。选择可用队长后再试。服务端校验归属变动与新执行请求，归档期间竞争写入的请求也必须遵守同一规则。迁移只对后续业务操作生效，保留旧版本已经写下的历史。

## 任务详情与关联链接

从项目任务页打开「实现上传重试去重」。正文、前置交付和动态可独立滚动，评论编辑区固定在下方。正文附件工具和评论回形针选择的文件都进入同一条待发送评论。可用 ⌘ Enter 或 Ctrl Enter 发送，刷新后从任务动态打开附件。点「订阅」可跟进本任务，旁边的加号可查看或更改订阅者。

在描述下方添加关联链接，填入 HTTP(S) 地址和可选名称。刷新后核对名称与链接目标，移除时可取消。迁移 659 为旧引用保留 ID、地址和创建人，缺省名称显示域名。

在任务属性栏打开截止日期，直接输入 YYYY-MM-DD 后按 Enter，也可切换月份、点选日期、选今天或清除。非法日期及反向区间会在日历内提示；Esc 放弃输入。更多属性里的标签支持中英文逗号，Enter 或移开焦点提交，Esc 放弃。提交沿用与表格相同的服务端版本校验。

在任务右栏点「发起会话」。任务名称和编号仍可见，拖动分隔条或使用左右方向键调整聊天宽度。侧聊会把本次讨论的最近几轮随当前问题发送给 Work；关闭或刷新会丢弃内容。服务在读取原会话材料和交付回复时都重新检查访问权限。

## 查看文件与回到来源

从首页问 Work「在哪里查看我的文件」，打开结果卡片。可组合文件类型与关键词，按名称、上传者或来源查找。在同名结果中按来源打开详情。「查看来源」定位到原评论或会话消息。把文件详情刷新，再关闭并刷新，可分别验证恢复详情和回到列表。一个有存储内容的零字节文件也能下载；旧记录只有名称时，详情中提供元数据说明。

## 从源码构建

按[仓库的冻结源码说明](../../README.md#从冻结源码重建桌面包)设置三个源码路径与工具变量后执行：

```sh
pnpm install --frozen-lockfile
scripts/local prepare
pnpm check:types
pnpm build
pnpm test
scripts/build-desktop
```

服务改动分布在 [V3 增量补丁](../../deploy/v3/backend.patch)、[Go 服务与数据迁移](../../deploy/v3/server) 和 [种子事务](../../deploy/v3/server/internal/handler/demo_workspace.go)。[前端模块](../../packages/ui-workspace-shell/views) 使用带工作区的 Host 传输。部署器使用的预构建渲染包为 `deploy/renderer.tar.gz`。

## 运行隔离验收

以下命令使用测试端口和独立资料目录。准备步骤在此目录构建自己的二进制和数据库。每次服务测试都创建新用户和新空间。服务测试中的时间推进及离线运行时绑定只访问本机测试库。

```sh
export WORKBENCH_TEST_LAB=1
export WORKBENCH_RUNTIME="$PWD/.local/v3-validation"
export MOBILEWORK_WORK_ADAPTER=mock
scripts/local prepare
scripts/local start api
scripts/local start a
scripts/local start b
pnpm test:v3:service
MW_V3_EVIDENCE="$PWD/.local/v3-clean-browser" pnpm test:v3:desktop
```

服务测试需要 `WORKBENCH_PG_BIN` 指向含 `psql` 的 PostgreSQL 工具目录。浏览器测试需要 Chrome 和 Playwright。两个 Host 分别在 19116、19117，API 在 19115，PostgreSQL 在 54459。测试只读各自的本机启动入口文件。截图默认在 `.local/v3-browser`。输出目录可用 `MW_V3_EVIDENCE` 指定。测试适配器只替换模型输出，身份、成员、搜索授权、数据库事务、收件箱、队列和原字节下载使用实际服务。

桌面包生成后，先停止上面的两个 Host、API、数据库，释放测试端口，再运行：

```sh
scripts/local stop b
scripts/local stop a
scripts/local stop api
scripts/local stop db
scripts/build-desktop
MW_V3_NATIVE_APP="$WORKBENCH_RUNTIME/desktop/Team Workbench.app" MW_V3_EVIDENCE="$PWD/.local/v3-native" pnpm test:v3:desktop
```

包内两个独立的 Electron 实例通过测试专用的隔离回放启动参数连接各自的 Host。每个实例各自注册和登录，测试完成关闭窗口。启动参数及调试端口见三身份脚本。独立构建目录和账号资料互相分开。验收范围、Mock 和未验证分项见[业务矩阵](验收矩阵.md)。

## 重启后持久化

在隔离测试目录启动 API 后，执行 `node tests/v3/restart.mjs`。该脚本新建两个账号、一个项目、一条任务和一段带附件的私聊，停止本测试目录的 API 和 PostgreSQL，再启动并重新登录。断言检查原 ID、参与者、附件字节、消息和重放回执。复验独立部署时，可设置 `MW_V3_DEPLOY_ROOT` 指向独立安装目录。运行时需要 `WORKBENCH_TEST_LAB=1` 与 `WORKBENCH_RUNTIME`。当隔离目录没有模型配置时，脚本还会暂时关闭 Mock，验证普通生成请求返回 503、没有成功消息，手动任务仍能落库，最后恢复原测试配置。

## 临时 Work 侧聊

从任务详情点「发起会话」，或从会话右上角进入临时 Work。可添加、移除并发送本次文件，发送时可选当前团队内的项目。每条最多四个附件，每个最多 3 MB。文本作为可读材料，二进制附件向文字模型提供名称和字节数。临时附件只在当前面板内提供原件下载。选择的执行权限是本轮偏好，服务端仍逐次检查来源和项目的访问权。关闭或刷新清空临时内容和选择。

## 任务表格的列与操作

从「全部任务 → 显示 → 表格」进入。在「显示列」点选开始日期或标签。看板、泳道和列表的「卡片属性」分别可显示描述、标签及开始日期。表格和卡片上的日期与详情共用日历，支持键入、日期范围校验、清除和 Esc 取消。标签支持中英文逗号，按 Enter 或移开焦点后一次提交整组，Esc 放弃编辑。若另一成员已修改任务，服务返回版本冲突，刷新后可根据新值重试。CSV 包含当前显示的列和所有符合筛选的页。

任务行末的菜单可编辑、置顶、复制、选择和删除。置顶归属当前账号，分页与导出使用同一排序。在同一置顶状态内，表头上一次选择的列决定升降序。复制成功后可打开副本，删除前会显示目标标题并要求确认。

## 手动执行与重复请求

任务详情的属性修改和评论只更新任务数据。在「执行日志 → 运行智能体」确认请求后，服务把当前成员的请求编号、任务编号和入队结果保存在同一笔数据库事务。「我的执行请求」按任务和登录成员列出请求编号、入队结果及其对应的队列编号或失败原因，刷新后仍可回读。重放返回原队列编号；原执行已经结束也沿用同一回执。显式重试会建立新的请求并关联历史执行。任务状态、站内通知和队列执行状态分别读取。可运行 `pnpm test:v3:service` 复验并发双击、完成后重放、改用同一编号操作其他任务、失败回执及跨工作区拒绝。

## 内置 Work 的可用状态

智能体目录和协作空间的在线数使用当前工作区服务返回的模型就绪状态。未读取到状态时，目录会显示「状态未知」。在无模型配置的隔离部署中，运行以下命令可一并检查目录的离线提示、空间在线数、生成失败及手动任务保存。该分支还需要 Chrome 与 Playwright。

```sh
MW_V3_VERIFY_OFFLINE_UI=1 node tests/v3/restart.mjs
```

## 三个身份复验邀请与通知

所有者在协作空间的成员管理中定向邀请两个测试账号。一位成员可从自己的个人空间打开右上角通知，选择团队邀请，刷新确认页后接受。另一位成员从邀请提示加入。所有者可从通知中心分别将一项和全部结果标为已读，再切到「全部」回看。服务集成还在新账户上测试撤销、已接受邀请重放、角色变更和移出团队。两类工作区共享数据库，读取回执时均按账号和工作区检查权限。

## 数据库升级和打包复验

测试需要 Python 3，SSH 桌面回放还需要 Python Playwright 和 macOS 辅助功能权限。打包的 A、B 实例共用隔离测试库，C 使用 Chrome 独立身份连接 B 的 Host。为避免争用同一套测试端口，请顺序运行下面各项。在以上述源码方式生成桌面包时记下其实际绝对位置。

```sh
python3 tests/v3/migrations.py
python3 tests/native/runtime.py --app "$WORKBENCH_RUNTIME/desktop/Team Workbench.app" --output "$PWD/.local/v3-packaging"
tests/v3/go-tests.sh
```

Go 脚本按锁定的提交和产品补丁组装源码，运行规划、Work、Qoder 执行桥及目录/凭据处理测试。Qoder 桥的上游 HTTP 行为用协议测试端模拟。

迁移脚本在当前运行的隔离 PostgreSQL 实例内创建一次性数据库，验证全新安装、已有同名 Work 的 V2 数据升级、655 版既有单附件的 ID 与字节兼容、重复迁移、V3 回滚与重新升级。测试结束删掉自己创建的数据库。若用打包客户端默认回放目录，可单独执行以下命令。

```sh
WORKBENCH_TEST_LAB=1 WORKBENCH_RUNTIME="$PWD/.local/v2-runtime/isolated-replay" MW_V3_PAYLOAD="$PWD/.local/v2-runtime" python3 tests/v3/migrations.py
python3 tests/native/remote.py --app "$PWD/.local/v2-runtime/desktop/Team Workbench.app" --output "$PWD/.local/v3-ssh"
```

SSH 测试使用本机受控服务验证真实协议和凭据归属。回放收集的 JSON、测试账户图片和 CSV 在对应输出目录。正式密钥、登录 cookie 和数据库凭据不应加入版本库。


## 外部运行与凭据

本机运行时提供真实的守护进程和 SSH 连接。Qoder Cloud Agents 入口读取服务端连接状态，由工作区管理员验证令牌、选择供应商环境和配置并发及超时。服务端在本机私有资料目录生成 32 字节加密密钥，保存已授权的连接配置。迁移运行资料时应同时保留 `provider-encryption-key` 及数据库。真实模型、供应商账户和异地物理设备的验证范围见验收矩阵。

## 从账户菜单复验个人设置

- 在「账户管理」核对当前身份，取消退出后应能继续操作。确认退出后刷新应回到登录页，另一账号仍能工作。
- 「系统设置」的语言、字号、主题和关闭行为在选择后保存到设备资料目录。「软件配置」可复制版本信息、查看快捷键并保存开机启动偏好。账号指令在「个性化 → 保存指令」提交，手动记忆在「记忆 → 编辑 → 保存」提交。切换账号后检查两者的隔离。
- 在「模型」添加样例名称，用大小写不同的同名文本重复添加，再分别取消及确认移除。样例名称只影响本设备的展示清单。安全和审计页面可查看实际接入范围，帮助和反馈页面提供手册、反馈渠道及产品版本。

## 运行时目录复验

1. 以团队所有者打开「协作空间 → 运行时」。首次使用时机器列表为空。从右上角加号启用本机执行端，等候守护进程向服务注册，再按在线或离线筛选机器。进入机器后可折叠属性栏、重命名，或清空名称恢复设备报告的名称。
2. 在机器内打开「查看日志」并刷新。桌面服务从当前账号的守护进程最近 200 行日志提取启停、注册和心跳事件，仅返回时间、级别与事件名称。重启操作分别等待停止和启动回执。另一个账号请求同一守护进程的日志会被拒绝。
3. 进入某个执行端，保存 1 至 50 的并发上限并刷新，再留空保存即可解除限制。「智能体」读取已绑定该运行时的可见智能体，「用量」按周期读取服务端实际计量。收回共享时，如果存在受影响的绑定或运行，需核对服务返回的影响清单后确认。
4. 从目录的加号或机器详情添加自定义运行时。填写 Harness、名称、可执行文件和参数，保存后回目录检查，再用普通成员验证管理权限。配置归属工作区，默认停用。启用配置后，具备该可执行文件的守护进程可按配置注册。机器清单仅计入服务已经登记的实例。
5. 复跑 `node tests/v3/service.mjs` 核对运行时负载。测试在隔离库中写入带唯一 ID 的排队、运行及完成记录，并在结束时清理。查询按团队、运行时可见性和授权账号过滤。实际入队、领取、开始和结束另由桌面执行测试覆盖。

## 更新独立部署包的前端

修改 React 页面后，`pnpm build` 写入各插件的 `dist`。在仓库根目录执行以下命令，将五个插件的脚本和第三方声明更新到独立部署器读取的归档。桌面打包器从同一组构建产物组装应用。

## 复现设计对照图

在仓库内的 `mloop/design-v3` 目录启动 `node serve.mjs`。回到仓库根目录，完成上面的客户端回放后执行以下命令。Chrome 和桌面包使用的 Electron 分别从「新建演示工作区」走同一套原型。Electron 原型使用一次性资料目录，退出时清理。两边的内容视口均为 1440 × 900。

```sh
node tests/v3/reference.mjs
MW_V3_REFERENCE="$PWD/.local/v3-reference-electron" \
  MW_V3_REFERENCE_ELECTRON="$WORKBENCH_V2_SRC/node_modules/.pnpm/electron@35.7.5/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron" \
  node tests/v3/reference.mjs
python3 tests/v3/visual.py --reference .local/v3-reference \
  --desktop-reference .local/v3-reference-electron --desktop .local/v3-native \
  --browser .local/v3-clean-browser --output docs/v3/证据
```

合成脚本需要 Python Pillow。两套客户端的系统设置回放同时采集浅色和深色的 35 个有效颜色值。退出设置并重载后仍应读到设备保存的深色偏好，选择跟随系统后再核对系统切换。整幅对照取同一 Electron 引擎的两份截图，按 ICC 配置统一到 sRGB。施工蓝图与项目任务页另记录控件边界、字号、行高、字重及 sRGB 颜色，分别与各自引擎的原型逐字段比较。报告保留原始小数坐标，允许的边界误差最多为 1/64 CSS 像素，字体尺寸、字重、行高和取样颜色须相同。任务详情另采集十九处控件，覆盖正文、前置交付、固定评论框、属性选择、日期、更多属性及折叠日志。文件页采集标题、范围、类型、搜索和首行。另按 SVG 的画布、尺寸、描边和图形属性核对任务栏与运行时的七个图标。按客户端引擎保留各自的原型坐标。运行时按实际可见 CSS 边界采集，保留布局测量。只复验原生客户端时可省去 `--browser` 参数。
