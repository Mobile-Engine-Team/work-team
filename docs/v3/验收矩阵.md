# MobileWork 第三版正式服务验收

基线为 work-team 的 d2cf705。原型按仓库内的[使用与实现手册](../../mloop/design-v3/docs/使用与实现手册.md)、[全场景验收](../../mloop/design-v3/docs/全场景验收.md)和[新团队协作验收手册](../../mloop/design-v3/新团队协作验收手册.md)走查。真实客户端经 DSH Host 转发至 Multica Go API，数据保存于 PostgreSQL。源码部署通过基础补丁与 deploy/v3 增量从冻结上游重建，页面在 packages/ui-*，执行端在 packages/execution-bridge。

S 对应 [多身份服务集成](../../tests/v3/service.mjs)，B 对应 [三身份客户端操作](../../tests/v3/browser.mjs)。脚本逐段断言并打印 PASS。结果截至本轮实际运行。环境和执行方式见[复验说明](运行与复验.md)。

## 首版交给测试的范围

独立部署和 macOS arm64 桌面包均已实测。测试人员可从左上角创建空团队，让第二个账号接受邀请，再创建项目、编辑并发布蓝图、核对原任务 ID、完成前置任务并查看交接回执。用第三个账号检查共享任务与私聊来源的权限边界。另一份独立演示工作区可用于复现手册样例。[启动和复验步骤](运行与复验.md) · [本次构建与运行记录](证据/运行记录.md)

归档样例 ANDR-110 的全局展示和已记录的界面差异留待测试反馈。模型生成使用显式 Mock 的场景、真实 Qoder 账号和第二台物理设备的验证范围见下表。测试发现权限泄露、数据丢失、重复发布建任务或回执与实际执行不符时，应优先按工作区、操作身份和任务编号复现。

## 已识别的口径冲突

- V2 的项目讨论和话题统计、会话模型选择均与 V3 冲突，采用 V3 三页签与服务端预配。
- 《新团队协作验收手册》第 3 节提到「允许会话调整模型」。按本次需求，会话沿用服务端配置，该开关及会话模型、执行模式选择器均不提供。「手动建任务／让智能体起草」只作用于任务表单。
- 原型表格的筛选复位按钮显示「清除筛选」，本版按《使用与实现手册》第 6 节使用「清除全部」，其作用是复位筛选。
- 原型的会话成员名单按显示名处理，还会列出具名的个人 Work。按手册第 3 节「其他人的个人 Work 不是你的代理」和本次服务端对象鉴权要求，会话所有者维护群名单，群内点名内置 Work 时使用发言人的授权上下文。其他成员的个人聊天记录和附件不会随名单开放。
- 原型按名称关联项目、使用浏览器身份和记录式派发。正式产品沿用 UUID、登录会话、PostgreSQL 收件箱和执行队列。
- 原型全局表格将 ANDR-110「已归档的旧排查记录」混在普通任务中。正式样例为它保留历史记录和编号，沿用仓库的活动任务查询，常规表格不会把这项历史记录作为可编辑或可推进的任务返回。这造成样例表格的一行可见差异。
- 工作区创建与演示样例分开。真实账号分别接受邀请。账户身份由登录会话确定。
- 原型在机器下模拟新增运行时。沿用仓库的运行时注册协议，从机器和目录创建的配置都归属工作区。所有者或管理员可以管理配置，设备注册后出现在对应机器下。
- 原型智能体和小队目录底部说明数据为演示、创建任务不会调用模型。正式目录展示数据库记录和服务就绪值，执行详情展示实际回执，模型适配方式见运行记录。
- 原型运行时记录不含真实凭据。正式版 Qoder 沿用 Multica 的受权连接服务和加密存储，访问令牌和仓库令牌不返回浏览器。只有连接成功后才可显示为可用。验收未连接真实 Qoder 账户。
- V2 的部分任务属性修改和评论会预览或触发智能体运行。本版把任务属性、成员评论和执行请求分开；正式客户端写入或修改评论时明确禁止派发。
- 手册第 1–8 节规定同来源、规范化标题相同的群内整理请求复用已有任务。群内 Work 操作按该规则复用，普通任务允许同名。显式交接成功依据站内消息或执行队列实际写入。
- 原生服务原先归档智能体时只取消执行队列，归档小队时转移所有指派。按 V3 手册修订为归档期间取消未完成业务任务或转交当前队长，保留已完成和已取消任务的历史归属。迁移 658 保留安装前已写入的历史记录。
- 本机原型走查中，“新版发布准备”样例确认发布曾提示“草案已变更，请重新打开发布预览”，历史面板保持为空。正式产品用自己数据库的版本和事务测试验收。

## 侧栏与已读回执

侧栏通过 `GET /api/workbench/navigation` 读取当前工作区、当前账号可见的数据。最近会话按照消息活动时间合并个人 Work、多人会话和用户发起的智能体对话；群内执行器的内部会话单独排除。任务关系来自真实指派、订阅、未读通知或当前用户可读的来源。文件夹以项目 ID 归组。迁移 653 把群消息中的成员提及与投递到该成员收件箱的事件绑定。迁移 654 在邀请事务内落库待接受通知和结果，首次创建个人空间时补投尚未过期的待接受邀请。点开会话更新本人的已读状态。
