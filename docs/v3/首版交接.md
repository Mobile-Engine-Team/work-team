# MobileWork V3 首版开发与测试交接

2026 年 11 月 28 日，首版进入多人业务测试。开发起点为 `d2cf705`。独立部署和 macOS arm64 桌面包均已跑通从创建团队到查看交接回执的流程。本次为 0→1 开发，后续优先修复阻断主要操作、影响数据或权限的问题。未妨碍主流程的界面差异集中记录，等测试人员补充影响范围后处理。[本次运行记录](证据/运行记录.md)

## 接手后先跑一遍

在 macOS 克隆本仓库，按 README 安装依赖，执行 `./scripts/deploy setup` 和 `./scripts/deploy open`。验证外部模型时另用 `./scripts/deploy model` 配置自己的凭据。浏览器、桌面包构建和隔离测试各自的启动命令见[运行与复验](运行与复验.md)。

| 操作 | 要核对的结果 |
|---|---|
| A 注册并新建空团队，邀请 B、C 分别登录接受 | 新团队的项目和任务为空，成员表有三人的独立身份。 |
| A 和 B 建项目，编辑施工蓝图，加入已有任务和拟新增节点，设置前置依赖 | 关闭预览、刷新，草案仍在；确认发布才生成拟新增任务。项目页和全部任务打开同一任务 ID。 |
| 尝试推进下游，再完成上游并重试 | 前置未满足时服务拒绝推进。满足后分别核对负责人站内通知、执行请求、实际开始和终态回执。 |
| A 和 B 从私聊消息创建团队任务，让 C 访问任务和来源 | C 可读取获授权的任务；私聊标题、消息和附件仍受参与者权限控制。 |
| 另建一份演示工作区，打开「移动端弱网上传」和「新版发布准备」 | 前者可从已发布的 V1 开始，后者可从未发布草案开始。两份团队的数据相互隔离。 |

多身份复验使用两个独立 Electron 实例和第三个 Chrome 身份。服务测试还覆盖并发发布、重复提交、非法依赖、删除项目后保留任务和会话、派发失败与重试，以及数据库重启后的回读。[业务验收矩阵](验收矩阵.md) · [从空团队开始的验收手册](../../mloop/design-v3/新团队协作验收手册.md)

## 测试基线和待反馈项

28 项业务场景中，22 项实测通过，5 项含显式 Mock，1 项因归档样例的全局展示口径待确认。独立部署通过 51 组服务断言和 37 组浏览器回放，打包端通过 45 组客户端回放。数字按各自脚本统计，覆盖内容有重叠。可用构建标识 `2f2ae0053b0a` 核对本轮桌面包；完整标识和渲染归档 SHA-256 见[运行记录](证据/运行记录.md)。

- **归档任务。** 打开演示工作区的「全部任务 → 表格」。原型可见 ANDR-110，正式版保存了归档历史，活动表格中 ANDR-109 后接 ANDR-111。全局展示和编辑口径待确认。项目推进已排除归档任务。
- **界面。** 已留存 38 组视觉对照。动态账号、头像和部分控件仍有差异。遇到遮挡、误触或无法完成操作，请附客户端、窗口尺寸和复现路径，便于区分交互故障与外观差异。[视觉证据与边界](验收矩阵.md#视觉证据与边界)
- **外部执行。** 模型文本与外部 CLI 响应使用显式 Mock 或协议测试端。登录、数据库、任务队列、站内送达和回执已实测。真实模型供应商、Qoder 账号及第二台物理设备留待具备环境时联测。[运行与复验](运行与复验.md)

反馈数据或协作问题时，请附构建或 Git 提交、工作区、操作身份、相关项目或任务 ID、最短操作步骤，以及期望和实际结果。派发问题再附请求或回执 ID，方便开发人员区分请求未入队、执行失败与客户端显示错误。
