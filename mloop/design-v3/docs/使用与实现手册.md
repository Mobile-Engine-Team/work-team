# MobileWork 第三版 · 本地使用与实现手册

适用范围：`design-v3` 本地原型。本文将**当前实现**与**正式服务建议**分开。不要把同浏览器多标签页演示当成多人联网测试，也不要把 Mock 提示当成任务真正在外部启动。逐项复测见[全场景验收](全场景验收.md)；从零搭建三身份弱网演练见[新团队协作验收手册](../新团队协作验收手册.md)。

## 1. 安装、数据和导航

1. 在 `design-v3` 执行 `node serve.mjs`，用浏览器打开 `http://127.0.0.1:8086/`。端口占用改用 `node serve.mjs 8087`；用浏览器时保持地址及端口不变。不要双击 HTML 用 `file://` 打开。无需 npm install、后端、登录、额度或 API Key。只编辑手册不需要构建；改了 React/样式才需按 README 构建。
2. **左上团队 → 新建演示工作区**直接跳转全部项目。每次创建新团队 ID 而非覆盖旧团队；同名演示空间可用各自地址中的 `team` 或团队设置中的标识区分。「移动端弱网上传」有 V1、依赖、评论附件和交接待办；「新版发布准备」有未发布草案；「体验调研」为空。还有跨状态任务、无项目/无负责人、归档记录、不同访问范围的智能体、混合人/智能体小队、交付协作会话和灰度私聊。日期相对创建日生成。
3. **创建团队**是另一入口：队名必填（最多 30 字）、描述可选（200 字）、头像可换颜色或选图片。提交后选择**进入团队**或**邀请成员**，后者打开成员管理；不灌入项目或任务。提交前**取消**不创建，成功页关闭不回滚。下拉可搜索/切换团队，当前项有勾；切换不会把任务搬到新空间。标准工作区可能预置内置 Work，不代表创建了自定义智能体。
4. **账户菜单 → 切换当前用户**只影响当前标签页及其刷新，不自动成为团队成员。显示同名测试成员时看邮箱：`member2@demo.invalid` 是演示空间成员，不等于 `linzhixia@example.com` 测试邀请身份。多身份验收应在**同一浏览器配置、同一地址的独立标签页**进行；新浏览器/无痕窗口不共享记录。**设置 / 帮助与反馈**打开对应面板；右上为版本和通知。收起/展开按钮、拖侧栏边界只改视图；窄屏按空间可用性覆盖打开，必要时展开侧栏。
5. 左侧**新建**打开会话/任务入口；**协作空间／智能体／智能体小队**为平级入口、使用各自页头；**最近会话**和**与我有关**显示按当前身份和空间整理的入口；**全部任务、全部项目**是固定看板入口。用户预设视图在看板视图内。退役的专家、市场技能/工具、独立定时任务旧链接返回同团队首页，不算缺失；任务详情中的唤醒功能与退役模块无关。
6. 浏览器站点数据是持久化来源；清站点数据或换协议/主机/端口相当于切换数据库，不能靠本地预览服务做跨机备份。导出 CSV 或下载交付文件不是整库导出。请只用测试数据，**不要录真实密钥或生产私密材料**。

### 快速走一遍：弱网项目交付

| 步骤 | 点击路径 | 检查点 |
|---|---|---|
| 1. 带样例开始 | 左上团队 → **新建演示工作区** → 点「移动端弱网上传」 | 总览有当前 V1；「体验调研」是另一张空卡，用于检查空状态。 |
| 2. 查计划和交接 | **施工蓝图**看 V1，再到**任务 → 查看可推进任务** | 「确定弱网复现条件」已完成；「实现上传重试去重」可推进；「验证重复上传回归」仍等前置。「整理交付清单」分给智能体。在演示空间勾选一项并确认，只生成本地回执。 |
| 3. 发布一个草案 | 回**全部项目 → 新版发布准备 → 继续编辑蓝图 → 查看变更并发布** | 发布前新增节点不在全部任务中；确认发布后查项目任务和版本历史。刷新页面，两边都从本地数据恢复。 |
| 4. 从结果回溯来源 | **全部任务**按项目和状态缩小范围，打开「确定弱网复现条件」，查看来源会话 | 源会话仍是「弱网上传交付协作」；在任务里点**发起会话**开的临时 Work 聊天不写回它。 |
| 5. 验证 AI 失败与恢复 | 新建 Work 会话发送「帮我整理一份本地操作检查文档【模拟失败】」；完成后去掉标记再发送 | 失败不生成交付物；成功产物可以下载；刷新原会话，两条记录仍在。 |

## 2. 协作空间、成员与邀请

| 入口/控件 | 操作、写入、异常与设计理由 |
|---|---|
| 空间资料卡、空间标识复制 | 查看名称、空间 ID、上下文。复制仅写入剪贴板，不改变标识。成员/智能体/小队/项目是空间数据，机器数量为设备级模拟环境；不要把在线计数当成心跳。|
| 编辑/查看空间资料 → 基础信息 | 所有者、管理员可编辑头像、队名、描述、智能体上下文（最多 2000 字）；**保存修改**显式提交，空名称不提交，关闭未保存内容时可放弃或返回。普通成员/访客仅看。上下文用来定义共同工作背景，不是每次会话的模型选择。|
| 管理成员 → 成员管理 → 成员 | 按姓名/邮箱搜索；行菜单**设为管理员／设为成员**即时写角色；**移出团队**需确认。不能用菜单改自己或移除所有者。成员名录变更不等于换成本地身份，也不保证清理历史发言或所有对象引用。|
| 邀请成员 → 创建邀请 | 支持逗号、空白、换行分隔多个邮箱，去重并校验，已在成员或待接受的邮箱提示冲突。选成员/管理员角色，提交进「待接受邀请」，**复制邀请**可从另一标签页打开；**撤销 → 确认**使未接受记录无效。不发送邮件。|
| 接受指定邮箱邀请 | 匹配当前测试身份；预设邮箱可用**切换测试身份**，切换不代表加入，需再点**接受邀请**。身份不符、撤销不写成员；已接受重复打开不新增成员。接收人和发起人可看到各自的本地通知。|
| 邀请链接 → 创建/复制 | 创建独立的通用链接，角色固定成员，默认 7 天；复制只取同浏览器地址。管理菜单可**停用链接／启用链接**，**删除链接 → 确认**删除。停用、过期、删除、别的浏览器无记录均不可加入；启用不会延长期限。|
| 通用链接的加入/关闭 | 打开后显示现在以谁加入，**加入团队**前再次校验链接，已有成员不显示加入按钮。关闭不写成员并清理地址 `invite`。不会发送邮件、短信或向陌生地址授权。|

**权限注意**：这里的管理写入与部分会话可见性是应用层演示。「访客」仍可能看到工作区页面；同一站点的存储和开发者工具可访问底层数据，不能据此宣称完成租户认证、退出登录或成员移除后的强制会话撤权。

## 3. 会话、Work 与任务来源

| 控件/动作 | 行为和设计理由 |
|---|---|
| 新建 → 会话 / 任务 | 会话输入空白时仅显示灰色建议；**填入建议**把文字放进可编辑草稿，不发送。切到任务使用独立任务入口，不在首条聊天时自动建任务。|
| 编辑、发送、换行 | Enter 发送，Shift+Enter 换行；输入法上屏不应提交，空文本且无附件不得发送。新会话在实际提交或明确创建/加入对象时才得到记录。未发送文本草稿按团队、当前身份、会话保留在标签页会话存储；附件暂存不保证刷新恢复。|
| `@` 菜单、成员、智能体、对话 | 从候选选择团队人、可用智能体或小队；不能任填一个陌生人取得数据。个人 Work 是内置智能体、已预配，所有会话都不选模型和模式。人对人普通消息不自动调用 Work；群中点名 `@Work` 或具体智能体才进入对应处理，小队会话可按成员/默认响应者交互。其他人的个人 Work 不是你的代理。|
| 附件、移除附件、消息附件 | 从系统文件选择器选择，发送前可取消/移除。可保留文件内容的本地记录可下载；已有旧记录可能只有名称。Mock 多数只读取名称，不做真实交付审核。存储满、读取失败不应宣称已上传。|
| 参与成员 / 会话设置 | 可改会话名；复制会话链接不新增成员；从空间候选邀请/移除参与者（不显示移除自己按钮）。入群可生成仅受邀者可见的历史摘要，避免把其他受限消息放进摘要。已有会话可改所属项目或输入**创建并关联**；同名用于关联现有项目。本操作不自动把全部关联任务迁移。|
| 复制会话链接、来源链接 | 只复制定位地址，不能越过应用的成员检查；私聊中找不到该会话与「任务可以打开」是不同权限判断。属于团队的任务不应因此泄露私聊标题或摘要。|
| 转为任务 / 将讨论整理为任务 | 群内**转为任务**先填可编辑的 `@Work` 请求，明确**发送**后本地整理、建任务并链接；同一来源、规范化标题相同的请求复用已有关联。会话设置的**将讨论整理为任务**还可打开明确表单，携带可见讨论与来源；保存才创建。回复**查看任务**和任务详情**任务来源**用于双向回溯。手工独立任务显示无来源。|
| 会话搜索、临时 Work 侧栏 | 搜索当前会话消息，点结果定位；临时 Work 可读取当前身份可见的原会话/任务作为上下文。临时讨论不会写回原群、不会进最近会话、不能作为分享记录；关闭或刷新清空，不改变主任务/会话 URL。群里直接发送 `@Work` 总结则属于正式群记录。|
| 功能卡片及入口 | 问「在哪里查看我的文件」「怎么创建项目」「如何邀请成员」之类问题，识别后显示可点击入口。卡片只导航/打开操作窗口，再由用户确认；不靠问一句话自动执行管理。退役模块不做推荐。|
| Work 进度及产物 | 模拟步骤切换及固定样例，普通请求约 4.2 秒结束；点步骤展开查看模拟细节，结果文档可下载。演示团队对普通请求加 `【模拟失败】` 可见失败且不产生新文件，移除标记重新发送是独立成功尝试；任务创建、入口问答和查询分流优先，不拿它们触发该失败。刷新可恢复会话记录。标题可沿用首条消息，不等同于本次执行结果。|

不接入真实模型、浏览器工具、邮件、仓库、语音转写或系统能力。输入区域若显示权限等能力设置，不能据此推断真实授权；临时/群聊/智能体入口有不同控件组合。人确认是从讨论跨到任务、从建议跨到变更的关键边界。

## 4. 搜索、通知、主动建议、动态看板与文件

| 入口 | 使用方法与边界 |
|---|---|
| 搜索、⌘/Ctrl+K | 用任务标题/编号、会话内容等关键字查找当前工作区；点结果跳目标，可 Escape 关闭。快速关键词不等于语义搜索。私聊和受限消息须先按当前身份过滤。会话内搜索不扩到其他对话。|
| 右上通知 | 切**未读／全部**，按邀请、任务、讨论等可见事件查看，开详情/动作或按**标为已读**，**全部已读**处理当前通知集合。关闭不等同已读；本地读状态不是操作已配送，不能作为真推送回执。|
| Work 主动建议 | 演示条件满足时提醒未分配、阻塞等；**为什么想到这件事**展开依据，**一起看一下**重验候选是否仍成立，成立才新建会话并发送对应查询；不会改任务或原会话。**一小时后再说**收起当前建议并免打扰一小时，不保证下次是同一条；**收起**只折叠。定时检查每 12 秒一次，另有打开页面 18 秒后的补查；页面隐藏、弹窗或任务侧聊打开、距最近键盘操作不到 8 秒时不主动弹出。自动展示至少间隔 3 分钟，同一候选 24 小时内不重复；状态按空间和身份保存。没有系统后台进程，不承诺离开页面后定时弹出。|
| 对话查询 → 视图预览 | 例如「查看『移动端弱网上传』的整体进度」或「只看已完成」。读真实本地任务生成视图；追问修改当前会话里的查询维度，结果随本地数据重新计算。未匹配有空态，不填造假任务。点卡片/侧栏的查看视图、预览切换在会话内打开或关闭右侧预览。|
| 视图版本、刷新 | 历史版保留当时的查询快照；**选择视图版本／回到最新版**只切展示。**重新查询并生成新版本**以当前数据写新快照。**在会话中修改／修改视图**先把本次输入指向选定视图，X 退出编辑指向，不回滚版本。|
| 固定、取消固定 | 固定后从左栏看板视图进入，同一查询仍可回来源会话；**刷新数据并保存新版本**不是覆写旧快照；取消固定后移除快捷项，不清空原会话。看板的自定义显示视图与会话查询视图是两套对象。|
| 我的文件（通过 Work 功能卡片） | **任务成果**汇总当前团队可见会话附件（含持久化 Mock 交付文件）和未归档任务评论附件。按类型、文件名、上传者/来源筛选，**清除筛选**复位。同文件被引用到不同地方是独立记录。点文件打开详情、**查看来源**定位、**下载文件**下载本地字节；仅支持受限的栅格图片预览，历史元数据条目不显示下载。**云端网盘**明确未接入。|

## 5. 全部项目 → 总览 → 施工蓝图 → 任务

### 5.1 管理项目

- **全部项目**：上方搜索名称/描述、选状态；没有匹配时清除筛选；无项目时新建。卡片显示状态、进度、负责人、日期和蓝图版本。进度按未归档任务、排除已取消的口径计算；空项目不是 100%。
- **新建项目**：填写名称（最多 100 字）和目标/验收标准，自由文本可空；提交时 trim，拒绝空或重名。创建完成进入总览，**不**自动发布蓝图或创建任务。卡片或回退箭头分别进入详情、返回全部项目。
- **项目设置**：改名、目标与交付标准、计划/进行/完成等状态、负责人、优先级、开始/截止日期。开始晚于截止拒绝。项目改名会同步任务、待创建请求、看板筛选、会话归属及未确认的会话任务建议；历史消息、已确认建议文本和查询快照保持不变。当前用名称做本地关联，改名后旧项目 URL 不保证可达，不能照搬成正式主键。**删除项目 → 确认**移除项目与蓝图，关联任务和会话保留，解除它们的项目归属；取消无写入。没有资源项或讨论页；来源讨论仍在统一会话。
- **总览**：看目标及交付情况、几组待推进/进行/待梳理任务；点行进真实任务。未发布只提供绘制/续编；已发布可进入正式蓝图或查看可推进任务。顶部仅「总览／施工蓝图／任务」，同一项目内切换。

### 5.2 绘制草案与审阅发布

| 按钮 / 区域 | 当前行为、约束、为什么 |
|---|---|
| 绘制蓝图 / 编辑草案 / 组织到蓝图 | 无草案时以当前正式计划或空图开始，已有草稿直接恢复。草案自动保存在当前空间，不写新的真实任务、不自动启动。正式版快捷打开真实任务，同时保留已发布快照。|
| 新增任务 | 创建拟新增节点，选中后填标题、交付要求、负责人和截止日期；先记录承诺再拆成执行队列。只有发布时分配真实任务编号。未发布时无真实任务可打开。|
| 加入已有任务 | 从支持的候选选择已有任务，不重复加入同一任务，不能借此抢占别的项目任务；未归属任务可纳入并在发布时落项目。取消不写。选中节点可查看原任务输入/打开真实任务（如果可用）。|
| 拖动、框选、多选、定位 | 拖节点只改布局；点击空白取消选择，Shift/框选收集选中节点供批量定位/AI 范围使用。**定位任务**聚焦节点；缩放按钮、比例、适应画布、自动布局用于阅读复杂图，不代表业务依赖变更。**撤销／重做**在编辑会话中反转图修改，不回撤正式发布或其他页面任务修改。|
| 添加前置任务 / 连接下游任务 | 方向是上游交付 → 下游使用。选端点后才创建连线，禁止自环、同向重复和有向环。选连线编辑「下游需要什么」，不与节点自身交付要求混淆。取消连线不写。|
| 删除连线 / 从图移出 | 删边只删关系；移出节点移除其关联边，现有任务、评论和结果仍保留。与任务详情的真正删除不是同一个按钮。|
| 同步任务最新内容 | 确认后对已有任务节点做基线、草案、任务当前值的三方比较。未修改字段取最新，用户明确修改保留；冲突提示，布局/连线及拟新增节点保留；同步不发布。|
| 用 AI 调整蓝图 | 选个体智能体，写目标/可选材料摘录，选整个草案、只新增或选区范围，**查看本次发送的输入**检查实际被纳入的项目/任务/摘录，不自动上传附件。**生成示例建议**出 Mock；勾选建议 → **预览采纳结果** → **采纳到草案**。只改草案，不替代人工发布。关闭不会派发工作。|
| 查看变更并发布 | 审阅新增/纳入、属性修改、交付依赖、移出；可填本次调整说明。空图、空标题、失效归属、无效依赖、任务约定冲突等不能被视为可安全发布。关窗口仍保留草案。点**发布 Vn**复核后写版本、创建拟新增任务（待规划）、更新现有任务的发布字段并清空草案。保留未被本次草案覆盖的实时任务字段；不自动通知或启动。|
| 版本历史 → 查看此版 → 返回当前计划 | 历史画布只读，标题/依赖按快照，任务状态为当前实时值，不是历史状态审计。返回恢复最新生效版，历史版不能用按钮改写。历史里已删除或移走的真实任务不能当可执行任务。|

### 5.3 项目任务与交接

1. **任务**页按当前项目显示已知任务及折叠的内部任务；内部条目不等同蓝图节点。**组织到蓝图**进入草案管理；项目页不增加「新建任务」快捷入口，可到全部任务明确选所属项目。点任务行打开任务详情，可回项目或任务列表，并通过**查看项目计划**回蓝图。
2. 详情在项目语境里显示**前置交付**和**直接下游任务**。只有真实上游为已完成才满足依赖；草案、已取消、仅记录过通知均不算完成。已完成的任务才显示对应的下游检查，直接下游不等于所有传递后继。
3. **查看可推进任务／查看下游交接**仅从当前正式版本取候选。已完成/已取消/不在版本/内部独立项不列为待推进；未交付、无负责人、进行中/审核中、阻塞、已记录分别说明原因并禁止勾选。草案新增/调整不参加。已归档或调出项目的任务不当作有效执行目标。
4. 勾选可推进项 → 查看本次确认 → **确认通知或请求执行**。成员对应「通知负责人」，智能体对应「请求智能体执行」文案；提交再次按版本与当前状态校验，结果明确为**已记录（未实际派发）**；相同版本/任务/负责人不重复记。不会发送真实通知、创建真实 run 或改任务状态。**完成并关闭／Esc**回原界面。正式服务必须把发送失败区分为可重试，不照搬此本地记账成“已送达”。

## 7. 智能体与智能体小队

### 7.1 智能体

1. **全部智能体／我的／已归档**改范围；搜索按名称/描述等，状态筛选区分在线和离线；列表/卡片只改变呈现；无匹配可重置筛选。内置 Work 是预配助手，默认角色和能力可作参考，不支持当作普通自建对象改名或归档。
2. **创建智能体**按向导填写显示名称、描述及指令、所需基础配置。必填、重名需校验，**返回／取消**不开始执行，**查看智能体**进入保存后的对象。模型是对象预配置；没有会话级下拉，也不会因「设置 → 模型样例」改变。
3. 详情**名称／描述／头像**快捷编辑；头像可用图片或色块。**属性栏**显隐、对象菜单**复制链接／复制 ID**不改变权限。**概览／工作**查看资料和任务；**分配工作**打开统一任务表单并预填；**全部工作**可按任务名搜索，点详情回统一任务。**对话**打开受支持的原型会话，回复是 Mock。
4. **设置 → 通用**编辑头像、名称、描述、开场和并发等可见项，通用表单字段有自动写入路径；空名、重名、无效并发不可保存。**访问权限**可选仅自己/整个工作区/指定成员，指定成员至少一个，保存改变可供提及/选择的范围；不保证所有本地 UI 等同真实授权。**环境变量**先解锁编辑区，再添加/删除变量，名称不能以数字开头、不能重复；本地明文仅用于假值。**自定义参数**每条按一个 token 顺序保存，空行不进入配置；不执行 CLI。切换/关闭时若存在未保存项，按该分区的确认选择保存/放弃，不盲目关闭。当前不恢复历史技能/MCP 配置。
5. 对象菜单**复制智能体**打开配置副本流程，确认才创建独立对象；**归档**需确认，从活跃目录移除，历史保留；未完成的关联工作按当前规则取消。**已归档 → 恢复**恢复条目可见/可选择，不自动重开旧任务。线上迁移还应验证所有转移和任务边界。

### 7.2 智能体小队

- **全部小队／我创建的／搜索／布局**便于发现小队；**创建小队**填名字、描述、指令并指定队长；从详情管理成员选择已有团队成员/智能体，避免重复加入。小队与个人智能体同属工作目录，但有独立成员关系、工作队列及对话入口。
- **更换队长**只选可用智能体；小队设置及简介可更新；成员菜单**编辑角色／移除**管理协作分工。角色文本不是工作区角色。成员、队长、对话与历史任务不应被当作同一条关系批量覆盖。
- **对话／分配工作／全部工作**使用统一会话和任务；@小队是让队内可用人员、代理参与，而非向名称相似的对象发消息。**归档小队**带确认，并提示未完成工作转交队长；当前没有小队恢复入口，切勿把智能体恢复路径照搬到小队。

## 9. 正式产品实现契约（建议，不是原型已上线能力）

### 9.1 对象与权限

- `Workspace(id)`, `User(id)`, `Membership(workspace_id,user_id,role,state)`；人/智能体/小队统一引用 `{type,id}`，显示名只做显示。工作空间范围写在每个业务实体上，后端从鉴权上下文取 workspace/actor，并对对象及字段重校验，不信任 URL/前端角色。默认拒绝跨租户枚举；成员移除即时撤回鉴权票据与缓存，明确已发任务和历史数据的保留策略。角色的调整权限、防止越权授予、所有者交接单独建规范。
- `TeamInvite(id,workspace_id,token_hash,email?,role,issued_by,expires_at,revoked_at,accepted_by?)`。邮件定向凭证不可转发身份；通用链接不授管理员，可配置使用限额。接收在事务内验证 token/有效期/状态/身份，`(workspace_id,user_id)` 唯一，重复请求返回已有归属。发送与配送结果走队列，不能以“生成 URL”当作已送达。
- `Project(id,workspace_id,…)`, `Issue(id,project_id?,parent_id?,…), IssueComment, Attachment, IssueSubscription, Conversation, ConversationMember, Message, Visibility, TaskSource, TaskLink`。任务创建来源与多会话链接分开；来源授权不足展示不含原名的通用提示。可访问任务不等于可访问原私聊或附件。项目改名不改 ID；删除项目事务里脱钩现存任务及当前会话的项目关联，历史记录保留快照，权限稳定。不要按显示名称连接生产外键。
- `Agent(id,profile_config_id,…), AgentGrant, Squad, SquadMember, Runtime, Machine`。区分内置个人 Work、可分享智能体、编排小队、运行能力与被授权使用。归档及时刷新分配目录、当前队员和后台执行权限；历史活动不硬删；迁移与取消的业务规则必须可追踪，不依赖客户端字符串批量匹配。

### 9.2 项目、蓝图、手动推进

1. 以 `BlueprintDraft(project_id, base_version, revision, editor)`, `BlueprintVersion(project_id, number, graph_snapshot, author, note, published_at)` 建模。节点 ID 稳定，拟新增节点不带 issue ID；依赖边 `{from,to,handoff}` 有方向和唯一约束；记录图schema 版本、基线任务字段和草案 revision。任何同步/撤销/AI建议采纳是草案修改，使用 `If-Match` 或 revision，冲突返回 `409` 和可比对字段。不能因为保存布局而写任务状态。
2. 发布预览计算新增/纳入/字段/边/移出；正式发布携带预览的草案 revision、当前基准版本和幂等键。服务端重读任务归属/权限/状态、验证非空标题、无重复/异租户/环/悬空引用、目标版本和同字段冲突。在**一个事务**中创建新任务、更新允许字段、生成快照、推进当前指针、归档草案；失败不留半套生效数据。并发重试返回同一版本编号，绝不能重复建任务。移出图不删任务。
3. `GET` 推进候选返回正式版 version、issue/owner、直接前后关系、明确阻塞码（`PREREQUISITE_UNMET`, `UNASSIGNED`, `BLOCKED`, `IN_PROGRESS`, `ALREADY_REQUESTED` 等）。只可对当前正式版可推进任务提交；UI 先显示所选成员/代理与预期动作。提交重验权限、版本、前置完成和最新负责人/在线策略。提交时创建 `HandoffRequest` + outbox，同事务写入唯一幂等键如 `(workspace,project,version,issue,assignee,kind)`。派发工作者消费并去重，分别记录 accepted/queued/sent/failed/cancelled；失败可按同一 ID 重试。接到通知不等于任务进行中；开始、完成及验收须有独立授权事件。
4. 后端表格支持服务端组合筛选/分页，优先级/状态排序固化且稳定（平局按 ID，空日期明确放尾）；看板拖动通过分组字段更新与 rank，冲突时给出可恢复反馈。业务状态转换、日期、并发写和批量返回按单条原因明确说明，不靠前端排序或 localStorage 作为真相。

### 9.3 会话、文件、通知和 AI

- 消息写入带 `client_message_id`（会话内幂等）、服务端时间、成员权限及可见域。分页/检索/推送前先筛选可见性；用户退出后 WebSocket/SSE 订阅需重验。临时 Work 使用受限短生命周期上下文，不出现在正式聊天历史，基于 source ID 加载可见消息，不把不可见内容送入模型或摘要。消息转任务的去重键须为具体操作/请求，允许用户明确创建同名不同任务；来源信息仅在可见时展示。
- 附件使用独立对象存储、受限签名 URL、大小/类型和扫描状态、内容指纹与上传提交分离；附件 ACL 随所属对象检查，不能以可猜 URL 下载。应用只展示安全内容并下载原字节；任务链接引用不等于上传。清理孤立或撤销的对象；源消息、评论、任务保留审计链。
- `Notice(inbox_owner,object_ref,kind,event_id)` 与 `NoticeReceipt(read_at, delivered_at)` 分开。事件起源/查询结果/提及/接受邀请可去重生成提醒；已读不代表批准或真实送达。建议卡的信息来源需最小化并解释，节流/免打扰须按身份；关闭/延后不同事件。定时唤醒用幂等调度器、服务端 UTC 和用户时区，赋予明确的取消与故障记录。
- AI 按 `Agent.profile_config_id` 与作用域授权选择预配路由，不接受消息随意覆盖模型。`AgentRun` 独立的 queued/running/succeeded/failed/cancelled，步骤和产物结构化，由用户批准后再提交业务变更；保存模型实际使用的受限输入/授权引用，不把模型或回复中的文字当指令权限。用量从可信执行端汇总；密钥进秘密存储，禁止下发到浏览器或记录到日志。允许重试不重复产生写入；取消/超时定义清楚。生产 Work 的提取、文件读取、模型/工具执行和服务回调都应由真实执行环境提供，而不是前端定时器。
- `ViewSpec` 保存结构化查询、过滤与数据范围，`ViewVersion` 固化快照、生成时间及数据版本；刷新再算必须重验读取权限，历史快照也遵守当前访问控制。固定是个人或工作区的独立关系，取消固定不删数据。配置按团队/个人/设备明确归属；订阅/收藏是关系表，不应沿用原型的单布尔字段扩到多人。
