# 从空团队开始：弱网上传协作验收

这份手册用一个案例串起三人协作：发现弱网上传失败 → 讨论重试规则 → 交给 Work 整理成任务 → 把验证事项建成独立任务并标为完成 → 查询项目进度。标出的输入可以直接复制。

## 0. 准备三个测试身份

1. 用一个**新的隐私窗口**打开 `http://localhost:8086/index.html?start=chat&team=product`，把它叫作 **A**。若本地服务没启动，在本目录执行 `python3 -m http.server 8086`。
2. 后面把两条邀请分别粘贴到**同一个隐私窗口**的新标签 **B**、**C**。三页要用同一地址和端口，不要混用 `localhost` 和 `127.0.0.1`，不要开三个独立的浏览器配置文件。原型使用同源的浏览器存储共享团队数据，并按标签区分测试身份。
3. 日常切换用 **左下角头像／用户名 → 切换当前用户 → 选择身份**。只改变当前标签页，刷新后仍保留；切换不等于接受邀请。首次加团队仍按第 1 节操作。

| 标签 | 身份 | 本次分工 |
| --- | --- | --- |
| A | 肖叶茂（默认身份） | 创建团队、配置智能体、组织讨论和建任务 |
| B | 杨陈皓：`yangchenhao@example.com` | 接受邀请、参与私聊和群聊，提出验收标准 |
| C | 林知夏：`linzhixia@example.com` | 接受邀请、验证私聊不显示给第三人、参与群聊 |

**先检查输入框：** 新会话里灰色的「可以试试：…」只是占位提示，不是内容。空着按 Enter，不应发送。点击 **填入建议** 后才会成为可编辑草稿，也不应自动发送。直接输入 `我可以直接输入自己的内容`，应立即替代占位提示。这里不必发出这条草稿。

## 1. 创建空团队并邀请 B、C

1. A 点击左上角当前团队名 → **创建团队**。填写：

   | 字段 | 输入 |
   | --- | --- |
   | 团队名称 | `弱网验收组` |
   | 团队简介 | `用弱网上传案例验证本地团队协作。` |

2. 点 **创建团队**。在创建成功界面点 **邀请成员**；到团队成员页后再点 **邀请成员**。把以下两行粘贴到 **邀请邮箱**，保留默认成员角色，点 **创建邀请**：

   ```text
   yangchenhao@example.com
   linzhixia@example.com
   ```

3. 在 **待接受邀请** 中，从 B 对应行点 **复制邀请**，粘贴到新标签 B。C 的链接照做，注意别串用。每个标签先点 **切换测试身份 · 杨陈皓／林知夏**，再点 **接受邀请 → 关闭**。B、C 不需要输入密码。
4. 回 A 的 **成员** 页确认两条邮箱都进入 **团队成员**。关掉团队设置继续。

**预期：** 新团队没有业务任务或会话；邀请接受后，A 不用刷新就能看到其成为成员。B、C 左下角各显示自己的邮箱。

## 2. 创建智能体

1. A 打开 **协作空间 → 智能体 → 创建智能体**。向导里选 **本机 · Codex**，继续到配置页。
2. 使用下列表单值，完成创建后点 **查看智能体**：

   | 字段 | 输入 |
   | --- | --- |
   | 名称 | `弱网验收助手` |
   | 描述 | `整理弱网上传问题和验收清单。` |
   | 指令 | `先复述已知条件，再按步骤列出验收标准。` |
   | 访问权限 | `整个工作区` |

**预期：** 打开新智能体详情，能看到名称、指令以及运行时配置。这一步没有真正启动本机 Codex。

## 3. 验证智能体设置、对话和内置 Work

1. 在新智能体详情打开 **设置**，检查名称、指令、运行时。可在 **会话能力** 打开 **允许会话调整模型**；设置即时保存。
2. 关闭设置，点详情顶部 **对话**，发送：

   ```text
   请列出弱网上传重试的三条验收标准。
   ```

3. 返回 **协作空间 → 智能体**，打开列表里的 **Work**。可以点 **分配工作**，以默认负责人 `Work` 创建一个名为 `整理验收步骤` 的任务。然后点 **对话**，发送：

   ```text
   你好，帮我梳理验收流程。
   ```

**预期：** 两个智能体都通过同样的详情入口进入对话，能收到演示回复。内置 Work 的对话接到你自己的 Work 助手；从智能体详情发起的会话不显示首页推荐。

## 4. 创建智能体小队并加入团队成员

1. A 打开 **协作空间 → 小队 → 创建小队**。填名称 `弱网交付小队`、描述 `复现、修复并验证弱网上传重试。`，队长选 **弱网验收助手**，提交。
2. 在小队详情点 **添加成员**，勾选 `yangchenhao@example.com` → **添加所选成员**。成员区应有队长和 B 两位。
3. 点小队详情顶部 **对话**，发送：

   ```text
   @弱网验收助手 请把修复和验证拆成两步。
   ```

**预期：** 打开这个小队的会话，并收到被点名智能体的演示回复。

## 5. 个人 Work 对话与产品知识问答

A 点左栏 **新建**，在 **对话** 输入框直接发送，不需要 `@Work`：

```text
请告诉我在哪邀请成员？
```

**预期：** Work 返回 **邀请成员入口** 卡片。点 **打开邀请成员**，应真的打开当前团队的邀请表单。点 **取消**，退出弹窗和后面的团队设置即可。这里验证的是产品入口问答，不是联网搜索或企业知识库。

## 6. 两人私聊，再建三人群聊

### 两人私聊

1. A 点 **新建**，发送：

   ```text
   @yangchenhao@example.com 请私下确认验收安排。
   ```

2. 将 A 当前地址栏的会话链接复制到 B。B 应看到 A 的消息，回复 `我会负责验收。`。回 A 确认回复自动出现。
3. 把同一链接粘贴到 C。应显示 **无法访问此会话**，不显示正文或输入框。此项仅验证页面行为，不代表服务器鉴权或加密。

### 三人群聊和项目

1. A **重新点新建**，不要在刚才的两人会话里发送。发：

   ```text
   @yangchenhao@example.com @linzhixia@example.com 确认弱网时上传失败，要保留草稿并显示重试按钮。
   ```

2. A 点会话右上角 **会话设置**。把 **会话名称**改成 `弱网上传验收群`。在 **所属项目**区填 `弱网上传项目` → **创建并关联**。复制该会话地址，关闭设置。
3. B、C 分别打开这条**群聊**链接。B 发送：

   ```text
   我负责验证断网恢复后重试，验收标准是同一个文件只上传一次。
   ```

   C 发送：

   ```text
   确认验收后，把重试结果记录到看板。
   ```

**预期：** 三页看见同一个群名和项目，A 能收到 B/C 的两条回复，B/C 也能看到群内交流。私聊和群聊的输入框都不显示新会话建议。

## 7. 对比右侧临时聊天和群内总结

1. A 在群聊页点顶部 **Work 聊天**（按钮的悬浮提示；辅助名称为 **打开临时 Work 聊天**）。如果消息提醒盖住按钮，先点提醒右上角的 ×。
2. 在右侧输入 `总结关键结论` 并发送。等回复出现，应包含「保留草稿并显示重试按钮」等来自群聊的内容。主群里不应出现这条提问。关闭右栏再打开，右栏应是空的；再次关闭。
3. A 在**主群**的输入框发 `@Work 总结群聊消息`。这次总结应出现在主群时间线中，其他参与者可见。区分两种模式：**右侧临时聊天只供自己看；群内 @Work 的结果留在群里。**

## 8. 从群聊创建任务，核对「任务来源」

1. A 在群聊点 **转为任务**。它只在当前输入框填入可编辑草稿，不跳页、不自动发送。把草稿改成下面三行（中间留空行），再发送：

   ```text
   @Work 请分析当前会话记录，提炼可执行事项，创建任务并关联到本会话。

   修复弱网上传重试
   ```

2. 在 Work 回复卡上点 **查看任务**。确认打开 `修复弱网上传重试`，所属项目是 `弱网上传项目`，右栏 **任务来源** 只有 `弱网上传验收群`。点击来源，应回到原群。
3. 保存任务详情地址。B 或 C 用自己的测试标签打开同一地址，也应看到原群来源。若要验证私聊来源权限，在第 6 节的 A/B 私聊另外转一个任务（末行改为 `核对私聊验收安排`）。把**任务详情地址**给 C；C 能打开团队任务，但只会看到 **来源会话不可查看**，看不到私聊标题和链接。

## 9. 用任务临时右栏讨论，再从「全部项目」开看板

1. 回到 `修复弱网上传重试`，点右栏 **发起会话**。在 **Work 临时聊天** 输入：

   ```text
   任务讨论：恢复网络后，应保留原草稿并使用同一上传记录。
   ```

2. 等回复后点右栏 ×。再点 **发起会话**，应是空白。在输入框键入 `不会被记住的草稿`，不发送，刷新页面；临时右栏应关闭，重新打开仍是空的。任务地址和最近会话列表都不会增加临时记录。
3. 关闭临时聊天，在右栏 **属性 → 状态** 把 `修复弱网上传重试` 改成 **进行中**。
4. 在左栏点 **全部项目**（紧接 **全部任务**），打开 `弱网上传项目` 卡片。可在 **任务** 页查看项目任务。返回左栏 **全部任务**，点表格右上 **新建任务**，必要时切换为手动创建，填写：

   | 字段 | 输入 |
   | --- | --- |
   | 所属项目 | `弱网上传项目` |
   | 任务标题 | `验证断网恢复后可重试` |
   | 任务描述 | `关闭网络，恢复后点击重试，检查文件不重复。` |

5. 确认项目仍是 `弱网上传项目`，点 **创建任务**。打开新任务，**任务来源**应显示 **没有来源会话**。把状态设为 **已完成**，再点 **返回看板**。
6. 点 **显示 → 看板**。确认两个独立任务分别在 **进行中** 和 **已完成**列。

## 10. 在统一会话里生成动态看板，并追问

1. A 点 **新建**，在个人 Work 对话发送：

   ```text
   查看「弱网上传项目」的整体进度
   ```

2. 等右侧预览加载。应显示刚创建的 `修复弱网上传重试` 和 `验证断网恢复后可重试`，而不是另一份示例数据。
3. 在同一会话继续发送 `只看已完成`。结果应只保留 `验证断网恢复后可重试`。刷新页面，筛选后的视图仍可打开。

## 验收环境与限制

- A/B/C 是三个标签里的**本地测试身份**，不是真实登录账号；不会发送真实邀请邮件，也不会跨设备同步。不要在原型中存真实私密数据。
- 私聊和任务来源的可见性是浏览器原型中的规则，不代表生产服务端鉴权。
- 智能体回复、群聊总结、任务提炼和产品入口问答使用本地演示逻辑，不是已接入的大模型或企业知识库。动态看板读取本次操作生成的原型任务。
- 自动回归入口：`_src/verify-fresh-workspace.cjs`。它需要 Playwright 和 Chromium；默认访问 `http://localhost:8086`，可用 `MLOOP_URL` 和 `CHROMIUM_PATH` 指定预览地址和浏览器。
