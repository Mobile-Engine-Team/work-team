# Work 软件升级调研与 Demo 搭建

入口：`/work-upgrade-demo.html`。点击「开始一轮新演示」，创建独立的「Work 升级专项」空间。已有轮次可继续，不会清空原空间。左下角「升级演示」可展开、收起，步骤与记录刷新后保留。

这是一条前端角色演示：肖叶茂发起，杨陈皓确认产品范围，林知夏推进研发，林悦查看进展，Work 升级研究助手整理范围与验收依据。邀请不会发送到外部邮箱；演示控制负责切换本地角色和推进预设事件，页面里的会话、任务和图表使用同一份实际本地数据。

| 步骤 | 操作 | 页面中的结果 |
| --- | --- | --- |
| 1 | 创建成员邀请 | 成员管理中产生三条待接受邀请 |
| 2 | 关闭成员设置，点击「同事接受邀请」 | 三位同事进入空间，待接受邀请清空 |
| 3 | 确认研究助手名称，点击创建 | 进入原智能体详情，可继续修改配置 |
| 4 | 发送初步想法 | Work 展示处理过程，生成升级范围、交付物和确认事项 |
| 5 | 一起确认目标 | 同一会话中保留产品、研发、负责人各自的确认意见 |
| 6 | 生成任务草稿，然后点击消息里的「创建全部任务」 | 创建四项实际任务，带入项目、负责人和验收要求 |
| 7 | 点击「任务已创建，进入协作」，再点击「进入任务并协作」 | Demo 任务动态中出现调研结论、研发安排、研究助手验收清单 |
| 8 | 领导查看进展 | 林悦发出查询，卡片渐进生成：共四项，两项完成，两项进行中，完成率 50% |
| 9 | 同步兼容性阻塞 | 切回肖叶茂，兼容验证任务变为阻塞，并记录研发发现 |
| 10 | 停留约 20–30 秒，等待右下角自动提醒 | Work 根据实际阻塞与负责关系推荐关注项目，无需点击触发 |
| 11 | 点击提醒里的「一起看一下」 | 自动发送自然提问，渐进生成当前项目风险卡片；关注清单只有兼容验证这一项 |
| 12 | 展开路线，点击「已查看提醒，安排跟进」 | 进入兼容任务，新增迁移映射、回退路径与验收用例安排 |
| 13 | 完成跟进并复查 | 任务记录补充处理与验收结果，解除阻塞；林悦重新查询，完成率更新至 100% |

四项任务：

- 完成 Work 升级场景与能力调研 — 杨陈皓。
- 确认升级范围与 Demo 验收清单 — 肖叶茂。
- 搭建 Work 升级交互 Demo — 林知夏。
- 验证旧版登录态与升级兼容性 — 肖叶茂，林知夏协作。

可在任意会话手动补充：

- 「帮我看看『Work 软件升级』现在进展怎么样」（推荐使用中文引号「Work 软件升级」，或直接输入完整项目名）。
- 「帮我看看 Work 软件升级有没有卡住的事情」。
- 「查询一下肖叶茂最近的进展」。
- 「请告诉我在哪邀请成员？」。

提醒在输入、模态弹窗、后台页面时暂缓；同一信号不会频繁重复。新一轮演示使用新的空间，所以可以重新观察自动提醒。自然提问也可以直接在输入框发送，不必依赖路线按钮。
