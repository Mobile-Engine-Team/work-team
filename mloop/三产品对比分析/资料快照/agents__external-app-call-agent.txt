从外部程序向指定 Loop 智能体发消息

适用范围：包含 POST /api/v1/workspaces/:workspaceId/app-runtime/agent-messages 的 Loop 版本中的自建应用 → 指定智能体单次发消息功能；部署该版本之前，现有线上环境可能还没有这个入口。 本文按浏览器里的实际操作顺序写成，最后给出可直接运行的 curl 与 Python 客户端。页面用语以中文版 Loop 为准。

先看懂这件事

外部程序不能冒充某个用户直接给智能体发消息。正确做法是：先在 Loop 创建一个代表外部程序的应用，让它连回 Loop，给它一张应用凭证，把应用和目标智能体放进同一个频道，并只授权它联系需要的那个智能体。之后外部程序带着凭证调用 API；频道里显示的发送者是应用，Loop 只唤醒请求里指定的那个智能体。

这是一条异步通道：API 返回 202 sent 只说明消息已写入并已请求唤醒目标智能体，不表示智能体已经回复。回复先出现在 Loop 频道中，不会直接放进这次 HTTP 响应里。若外部程序还要自动收取回复，需要另行运行应用的 Runner 长连接，订阅应用被真正 @ 提及时的事件；应用详情的「快速开始」提供 Runner 示例。仅调用本文的发送脚本，不需要让 Runner 长期在线。

开始之前需要满足的条件
条件	说明
应用创建权限	工作区管理员/所有者可直接创建自建应用；普通成员需要先提交创建申请，等管理员批准后再继续（批准前页面显示「审批中」，还没有连接方式可选）。批准前不要签发凭证或调用 API。
目标智能体	存在要唤醒的智能体，并且它的主机/运行端能上线（否则消息能发出，但不会有回复）。
目标智能体在目标频道里的可见性必须是「频道共享」	手工把智能体加进频道时默认是「仅自己使用」（私有），私有智能体收不到应用发来的消息，接口会返回 403。必须在第 5 步把它改成「频道共享」。
一个投递频道	你有权把应用和目标智能体加入该频道。
网络可达	外部程序能通过 HTTPS 访问该 Loop 服务；本机测试可用 http://localhost:3001。不要把测试地址当成生产地址。

本功能复用应用已有的 messages.write 权限，不需要给人类用户新增角色或权限，也不要用个人登录 Cookie 代替应用凭证。

第 1 步：创建自建应用

先分清两种"应用"，否则页面一定对不上。

本文讲的是你自己创建的应用：详情页的「概览」里有「连接」「连接凭证」「快速开始」。
从应用市场已安装的第三方应用不适用本文：它的「概览」只显示「类型 / 连接数 / 我的权限 / 变更方式」（「类型」是「服务集成」），没有连接方式和应用凭证，也拿不到本文要用的凭证。要按本文操作，请先按下面第 2 条新建一个应用。
在目标工作区打开「能力库」→「连接器」（这里同时就是应用市场）。
点击页面右上角「创建应用」，在弹出的「创建外部应用」里填写应用名称和描述，提交。
提交按钮会告诉你接下来发生什么：工作区管理员/所有者点「创建应用」会直接创建成功；普通成员点的按钮是「申请创建应用」，提交后创建申请进入待审批。
普通成员在批准前看到的应用是审批中：详情页只有「概览 / 权限 / 审计」，不会出现「连接」「连接凭证」「快速开始」（也没有连接方式可选）。这是等待审批的正常状态，不是故障、也不是页面坏了，请等管理员批准后再从第 2 步开始。
创建完成后进入该应用的详情页。页面顶部的标题显示的是「应用集成」（侧边栏里那个入口才叫「连接器」），标题右侧是应用名与 @应用标识；用词不同不代表走错了地方。详情页有「概览 / 权限 / 审计」三个页签；后文用到的「连接」「连接凭证」「快速开始」都在「概览」页内，不是独立菜单，需要在「概览」页里继续往下滚。
应用名右侧有两个状态标签：已启用（应用本身可用）和 未配置（连接还没配，见第 2 步）。刚创建完就显示「未配置」是正常状态，不是故障——配好连接后它会变成 已配置。同时记下应用名称与 @应用标识。

建议用英文或拼音命名应用（例如 alerts-bot）。使用纯中文名时，@应用标识 会自动退化成 @app-1gj1tki 这类随机串，后续在频道里辨认、排查都更费劲。

页面会自动生成并固定一个合法的应用运行声明：包含 loop.message.mention 事件，以及 app.mentions.read、messages.write 两项能力。通过页面创建时不用自己手写 manifest。如果改用开发者 API 创建，必须按当前运行声明格式提供这三项；缺项会使安装/Runner 凭证或后续调用被拒绝。

第 2 步：给应用配置连接方式

在应用详情「概览」页里往下滚，找到「连接」区（标题右侧会显示「未配置」）。新应用都是从这里开始配置，先选择连接方式：

方式	什么时候用	说明
我的运行端连回 Loop（Runner 长连接）	推荐，尤其是在没有公网回调地址时	由你运行的进程主动连回 Loop。本 API 接受这种凭证。
Loop 推送到我的服务（HTTPS 回调）	你已有现成的公网 HTTPS 服务	Loop 把事件推给你的地址。它的签名密钥不能当 Bearer 凭证使用。
点击「配置连接」，选择连接方式。
若选 HTTPS 回调：地址留空会被提示「请输入有效的 HTTPS 回调地址」，非 HTTPS 地址同样被拒；点「返回」可以清掉本轮错误、重新选择。
选定「我的运行端连回 Loop」后，页面进入「已配置」：连接区会显示连接摘要和「更改连接方式」，同一页才会出现「连接凭证」（第 3 步用）和「快速开始」（第 9 步用）。在配好连接之前，这两个区块不会出现。
「更改连接方式」可以来回切换 Runner 与 HTTPS 回调，切换不会丢掉已有凭证。
第 3 步：取得应用凭证
还在「概览」页，向下找到「连接凭证」。
输入一个能识别用途的名称（例如 外部系统-生产），点击「新增凭证」。
页面会显示一次完整凭证明文，并提示「请立即复制并妥善保存。离开本页后将无法再次查看，只能重新生成。」
立刻复制到外部程序的密钥管理器或受限环境变量，然后点「我已保存，隐藏」。
之后列表中只保留一个前缀（例如 Iff-Z29w…）用于辨认。需要轮换时新建一把，把外部程序切过去后，将旧凭证「停用」——停用立即使其失效。

第一期这里复用的是原本发给应用 Runner 的凭证，外部调用与 Runner 共用这类身份。它只代表这个应用，不是任何人的登录会话。不要把凭证写进代码仓库、截图、工单或群消息。

第 4 步：开通应用权限，并授权目标智能体
切到「权限」页签。
「权限范围」确认这两项已开启：
「发送消息」（messages.write）—— 必须开启；
「读取应用提及」（app.mentions.read）—— 创建时通常已默认开启。 不要为此新增别的 permission scope。
「扩展权限」→「智能体」，把目标智能体对应的开关打开。开关即时生效，无需再点保存；未选择的智能体应显示关闭。

交叉验证（可选）：打开目标智能体 → 「能力中心」→「应用集成」，同一个应用应显示「已启用」。两处是同一条真实授权。

要停止外部程序联系某智能体时，关闭对应开关即可；即使外部程序仍持有应用凭证，新的调用以及同键重放都会被拒绝。注意这不会撤回已经发出的历史消息。

第 5 步：把应用和目标智能体放进同一个频道

这一步最容易出错，请完整读完。

在会话区点「+」→「新建频道」，填写频道名称。
在「成员」里，把应用和目标智能体都添加进来。
目标智能体右侧的「使用范围」必须选择「频道共享」：
「仅自己使用」＝ 私有，只有你能 @ 它。在这种状态下，外部应用发消息会返回 403 App agent target is not authorized for the target scope。
「频道共享」＝ 公开，频道内所有成员（包括应用）都能 @ 它。这是本功能要求的状态。
如果智能体已经以私有方式加入频道，请移除后按「频道共享」重新添加。
点击「创建频道」。创建后频道消息区顶部会出现「……将 X 添加到 Y」的系统提示，说明应用→该频道的目标绑定已建立。

单有应用凭证或智能体授权、但没有有效频道绑定，仍然不能向这里发消息。移除应用、停用安装或取消绑定后，新请求会被拒绝。

目标智能体的「自动唤醒」开关不必开启：这个 API 是明确点名智能体的请求，会尝试唤醒被点名的那个，不会顺带唤醒频道里其他智能体。

第 6 步：从浏览器地址取得三个 ID
参数	怎么找	示例格式
workspaceId	当前工作区页面，地址里 /w/ 后一段	ws_...
agentId	点开目标智能体，地址里 /agent/ 后一段	agt_...
targetScopeId	打开目标频道，地址里 /channel/ 后一段	chn_...

三个 ID 必须指向同一个工作区内刚才配置的对象。示例 ID 只是格式说明，不能照抄到你的环境。首个可操作流程建议使用频道；不要把频道显示名（如 #项目讨论）填进 targetScopeId。

第 7 步：发出第一条请求

把下面的占位值替换成自己的。生产环境务必使用 HTTPS，并从环境变量或密钥管理器取凭证；这里不展示真实凭证。

export LOOP_BASE_URL='https://你的-loop-域名'
export LOOP_WORKSPACE_ID='ws_你的工作区ID'
export LOOP_AGENT_ID='agt_目标智能体ID'
export LOOP_TARGET_SCOPE_ID='chn_目标频道ID'
export LOOP_APP_RUNNER_TOKEN='从连接凭证复制的一次性明文'

curl --fail-with-body -sS -X POST \
  "$LOOP_BASE_URL/api/v1/workspaces/$LOOP_WORKSPACE_ID/app-runtime/agent-messages" \
  -H "Authorization: Bearer $LOOP_APP_RUNNER_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: alert-20260927-001' \
  --data "{\"agentId\":\"$LOOP_AGENT_ID\",\"targetScopeId\":\"$LOOP_TARGET_SCOPE_ID\",\"content\":\"请确认收到这条来自外部应用的消息。\"}"


成功时 HTTP 状态是 202：

{"messageId":"...","status":"sent"}


拿到 messageId 后打开目标频道，应看到一条由应用发出的消息；随后由你指定的智能体回复。不要把 sent 当作已经收到智能体答案。若智能体没有回复，先检查它的主机/运行时是否在线，再检查频道消息与任务日志。

重试规则很重要

Idempotency-Key 必填，最多 255 个字符；建议只用英文字母、数字和 -，方便各种 HTTP 客户端发送。给每一笔业务请求分配一个稳定、唯一的键；网络超时重试同一笔时，保持键、智能体、频道和正文完全相同。这样重试会拿到同一个 messageId，不会重复发消息。新业务请求使用新键；不要把同一个键用于另一个智能体、频道或不同正文，否则通常返回 409。键按应用安装隔离，不要假设换频道后旧键就可复用。

可直接运行的外部客户端：Python 标准库

保存为 call_loop_agent.py（Python 3.9+，不需要安装第三方包）。它只负责发送；不会假装在 202 里拿到智能体回答。请把凭证放在进程环境中，不要写在文件正文中。

#!/usr/bin/env python3
import argparse
import json
import os
from urllib.error import HTTPError, URLError
from urllib.parse import quote
from urllib.request import Request, urlopen


def required(name):
    value = os.environ.get(name, "").strip()
    if not value:
        raise SystemExit(f"缺少环境变量 {name}")
    return value


def main():
    parser = argparse.ArgumentParser(description="用自建应用给一个 Loop 智能体发消息")
    parser.add_argument("content", help="要发送的文本")
    parser.add_argument("--key", required=True, help="本次业务请求的稳定幂等键；重试时保持不变")
    args = parser.parse_args()

    base = required("LOOP_BASE_URL").rstrip("/")
    workspace = required("LOOP_WORKSPACE_ID")
    token = required("LOOP_APP_RUNNER_TOKEN")
    agent = required("LOOP_AGENT_ID")
    scope = required("LOOP_TARGET_SCOPE_ID")
    url = f"{base}/api/v1/workspaces/{quote(workspace, safe='')}/app-runtime/agent-messages"
    body = json.dumps({
        "agentId": agent,
        "targetScopeId": scope,
        "content": args.content,
    }, ensure_ascii=False).encode("utf-8")
    request = Request(url, data=body, method="POST", headers={
        "Authorization": f"Bearer {token}",
        "Content-Type": "application/json; charset=utf-8",
        "Idempotency-Key": args.key,
    })
    try:
        with urlopen(request, timeout=20) as response:
            result = json.load(response)
            if response.status != 202:
                raise SystemExit(f"预期 202，实际 {response.status}: {result}")
    except HTTPError as error:
        detail = error.read(2048).decode("utf-8", errors="replace")
        raise SystemExit(f"Loop 拒绝请求（HTTP {error.code}）：{detail}") from None
    except URLError as error:
        raise SystemExit(f"连接 Loop 失败：{error.reason}；请用同一 --key 重试") from None

    print(f"已发送，messageId={result['messageId']}；请到 Loop 频道查看智能体回复。")


if __name__ == "__main__":
    main()


运行前设置与上一节相同的五个 LOOP_* 环境变量，然后执行：

python3 call_loop_agent.py '请确认收到这条来自外部应用的消息。' \
  --key 'ticket-12345-first-message'


若超时，原样重跑同一命令。处理下一张工单时换一个新键。真实业务里最好把键与工单/请求 ID 一起保存。示例不会自动保存或打印凭证。

如果要让外部程序自动接收回复

当前发送 API 没有"等待回答"模式，也没有按 messageId 直接取 Agent 回答的配套接口。若希望应用在 Agent 回复并真正提及 @应用 后收到事件，需要在应用「概览」→「快速开始」按 Runner 示例运行一个长期在线的接收进程，消费 /app-runtime/stream 的 loop.message.mention delivery，并按 Runner 契约确认处理。仅在正文里打出类似 @应用名 的普通文本，不保证形成可投递的结构化提及。普通使用者可先在 Loop 频道人工查看回复；不要把这个可选接收步骤当成发送成功的前置条件。

「快速开始」不是独立菜单，就在应用详情的「概览」页内，需要先展开。

常见结果与排查
结果	最常见原因	先检查什么
应用详情页只显示「类型 / 连接数 / 我的权限 / 变更方式」（类型是「服务集成」），看不到「连接」「连接凭证」「快速开始」，只有「卸载」	①你打开的是应用市场里已安装的第三方应用，不是自建应用；②应用还在审批中；③早期版本的一个缺陷：已配置连接的自建应用在刷新后被错误地渲染成这个形态	①按第 1 步新建自建应用；②等管理员批准；③该缺陷已修复，升级到包含修复的版本后不再出现。遇到时先把应用 @应用标识 反馈给管理员，不要反复删除重建（重建会丢掉已配置的连接与凭证）
403 App agent target is not authorized（不带 for the target scope 后缀）	目标智能体没有显式授权这个应用（与频道共享是两回事）	智能体 →「能力中心 → 应用集成」把该应用「启用应用」（应用「权限 → 扩展权限 → 智能体」是另一个开关，两处都要开）
403 App agent target is not authorized for the target scope	目标智能体在该频道是「仅自己使用」（私有）	把智能体的使用范围改成「频道共享」（见第 5 步）
403（其他情况）	应用/安装不活跃、缺 messages.write、目标频道未绑定、智能体不在频道	按第 2–5 步逐项核对
在频道里 @应用标识 之后应用一直没有回应（应用侧没回消息）	该应用没有在线运行端，或运行端用的是另一个应用的 Runner Token——一个运行端进程只服务一个应用；运行端离线期间的提及只会排队，等运行端连上后一次性补投（可能一次刷出多条）	应用「概览 → 快速开始」按示例确认运行端进程在跑，且 LOOP_RUNNER_TOKEN 属于这个应用；再发一次 @应用标识 ping 验证
202 sent，频道有应用消息，但暂未回复	智能体尚未完成运行；202 不是答复	智能体主机/运行时状态、频道中是否有后续回复
400	JSON 错误；缺 agentId、targetScopeId、content 或 Idempotency-Key；字段超出限制	对照请求示例；确认正文不为空、键不超过 255 字符
401	凭证没带、复制错、过期或已停用	应用「连接凭证」状态；必要时签发新凭证
409	同一键被用于不同请求；或触发应用通知限流（错误码 app_notification_rate_limited）	看响应中的 code/错误内容；不同业务请求换新键，限流则稍后重试
413	请求体超过 512 KiB	缩短正文；本入口只接受文本，不要把大文件塞进 JSON

幂等重放的一个边界：如果某条消息早已成功发出，后来只移除了频道绑定，同键、同内容的重放可能仍返回原来的 messageId；这不会重新发消息或再次唤醒智能体。新键请求会重新检查当前绑定并被拒绝。撤销智能体授权则不同：即使同键重放也会被拒绝。

交付前的核对清单
 应用「概览」显示已启用，连接方式是「我的运行端连回 Loop」。
 已新增连接凭证，且外部程序使用的就是它（明文只显示过一次，已安全保存）。
 应用「权限」里 messages.write 已开启；目标智能体开关为开启。
 目标智能体的「能力中心 → 应用集成」也显示该应用「已启用」。
 目标智能体在目标频道里的使用范围是「频道共享」（私有会返回 403）。
 需要应用主动回消息时，该应用的运行端进程在线，且用的是这个应用的 Runner Token（应用详情 →「快速开始」）。
 目标频道成员里同时有应用和目标智能体。
 外部调用得到 202 与 messageId；频道消息作者显示为应用而不是人。
 只有请求中点名的智能体被唤醒并在频道回复；若需要机器接收，另验 Runner 真正收到提及事件。
