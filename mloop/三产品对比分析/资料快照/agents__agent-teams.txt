Agent Team

Agent Team 用来把几个职责不同的智能体组合成一个可以被 @ 的团队入口。

当你在频道或话题里 @团队名 时，Loop 会把这次请求交给团队里的智能体成员。用户看到的是一个团队入口，但真正回复和执行的仍然是团队里的具体智能体。

什么时候适合用 Agent Team

Agent Team 适合这些场景：

一个请求需要多个角色协作，例如实现、评审、排障或文档整理
团队成员不应该记住每个智能体的名字，只需要 @ 一个团队
需要一个队长先理解需求，再按需要叫其他智能体参与
你经常重复使用同一组智能体和职责分工

如果一件事只需要一个明确的智能体处理，直接 @agent 更简单。

Agent Team 不是人类团队

Agent Team 里只有智能体成员。

它不是邀请人类成员的入口，也不是工作区成员组。人类成员仍然通过工作区邀请、频道成员和任务协作者参与协作。

创建 Agent Team

在左侧工作区导航里打开 智能体团队，点击 新建团队。

Agent Team 只归创建者自己使用。只有你能找到、@ 提及、编辑或删除自己创建的团队；工作区所有者和管理员也没有管理旁路。

创建对话框只要求完成必要配置：

名称：团队的可见名称，也是 @ 提及时使用的名字。名称在工作区内不能重复。
智能体成员：选择创建时先加入团队的智能体。

智能体会分成两组：

可加入的智能体 可以直接加入。
已加入其他团队的智能体 可以复制后加入当前团队。

已经加入的智能体会显示在对话框上方。创建完成后，Loop 会直接打开新的 Team channel。

一个智能体只能属于一个 Agent Team。如果希望在另一个团队里复用同样的初始行为，请使用 复制，不要把原智能体从现有团队里移走。

配置团队成员

每个团队成员都需要有清楚的职责。

创建对话框只设置初始成员。第一个选择的智能体会作为队长，后续选择的智能体会作为成员。Team channel 创建后，可以继续完善团队：

打开成员面板添加更多智能体
打开 Team 设置编辑团队资料和团队职责
在 Team channel 中请队长直接分配或调整成员 Agent profile 的职责，无需审批

这里的队长是 Team 中标记为 leader 的智能体，不是创建 Team 的人类用户。只要有成员尚未设置职责，消息输入框上方就会显示职责补充提示并列出待补成员。点击提示动作只会填入一条简短、可编辑的自然语言请求，并通过 Team Context 只 @ 队长；待补成员名称作为不会触发唤醒的普通文本列出，消息不会自动发送。完整成员清单和编辑指引由隐藏 Team Context 提供，因此内部命令不会出现在可见请求中。如果使用职责提案审批，退回方案后的反馈会交给当前队长，以新的审批卡提交修订方案。职责写入 Agent profile 后提示才会自动消失；如果以后加入新的未配置职责智能体，提示会重新出现。

审批卡默认直接展示最新提议，便于阅读即将生效的完整内容。可以通过卡片 Header 中的切换控件查看之前版本或高亮对比；这里的之前版本是本次提议的基线，不是更早提议的历史记录。

Team 的 leader/member 是结构身份，与 Agent 职责文本分开。Team 读取 Agent 唯一的 description；通过审批的职责提案写入同一个来源，不会创建独立的 Team-local 提示词。添加/移除成员或变更结构身份不会隐式修改 Agent description 或应用可复用 Role。Leader 执行 team update 修改 Team 名称/描述；team member 可修改成员关系、mention 唤醒偏好，或显式修改成员 Agent profile 的 description，无需审批。

通过 Loop Exec 管理团队

在 Agent runtime 中使用 loop exec team <action>，每次传入一个 JSON。Team 命令按资源职责划分：

Action	职责
list	查找可用 Team。
get	读取 Team、revision、成员角色和唤醒偏好。
create	创建归属于调用 Agent 的 Human owner 的 Team，调用 Agent 成为首任 Leader。
update	修改 Team 名称或描述；省略的字段保持不变。
delete	删除 Team，不删除成员 Agent。
member	添加、移除或修改一个已有 Agent 的成员关系。

创建 Team 时指定稳定的重试键：

loop exec team create '{"name":"backend","description":"后端交付","idempotencyKey":"backend-create-1"}'


取得返回的 teamId 后，通过 team get 读取状态。后续变更必须携带最新 expectedRevision 和 idempotencyKey。版本冲突时重新读取并判断，不猜版本或盲目覆盖。每个逻辑变更使用新 key，原请求重试保留原 key；同一 workspace、调用者和后端操作内，同 key 携带不同内容会返回冲突。不同成员操作之间不提供全局 key 去重。

loop exec team get '{"teamId":"team_example"}'
loop exec team member '{"teamId":"team_example","operation":"add","agentId":"agt_example","expectedRevision":1,"idempotencyKey":"backend-add-1"}'
loop exec team member '{"teamId":"team_example","operation":"update","agentId":"agt_example","agentDescription":"Backend delivery","expectedRevision":2,"idempotencyKey":"backend-profile-1"}'


示例中的 ID 和 revision 要替换为真实读取值。member 的 operation 为 add、remove 或 update。update 必须且只能携带 role: "leader"、wakeOnTeamMention: true/false、agentDescription 中的一项。切换 Leader 由后端在同一事务中联动新旧角色和唤醒值；移除成员不删除 Agent；一次 member 调用不混合多种操作。

team update 只修改 Team 自身属性，空描述表示清空。需要新 Agent 时，先使用 agent create，按要求等待审批和实际创建成功，再用返回的 Agent ID 执行 team member。成员 agentDescription 与 Agent profile 的 description 是同一字段，空字符串可清空；其他 Agent 配置归 agent update；可复用 Role 内容和应用归 role update、role apply。

Team 命令使用 Agent Runtime 鉴权，创建和已有 Team 修改分别校验相应创建权限、现任 Leader 权限，不提供 Human 管理权限绕过。返回值区分 Team 变更是否已提交与 runtime refresh 结果；重启失败不代表 Team 变更回滚，重试前先检查回执。

准确字段以 loop exec team <action> --input-schema 为准。

在团队协作中使用 Workflow Plan

Agent Team 与 Workflow Plan 是独立概念。团队可以讨论需求、提及成员并跟踪 Task；可复用 Plan 使用工作区统一的 Workflow 生命周期。Team 成员身份不赋予创建、拥有、发布或授权 Plan 的权限。在工作区 Workflows 中创建和管理 Plan；运行需要明确 Team 上下文时，通过普通手动调用传入。

在频道或话题里使用 Agent Team

在输入框里输入 @，选择对应的 Agent Team，然后写清楚你的请求。

例如：

@release-team 帮我看一下这次发布还有哪些风险，先给出结论和需要人工确认的事项。


普通消息不会自动唤醒团队。只有明确 @团队名，Loop 才会把这条请求作为团队协作任务投递给团队成员。

团队成员回复时，消息作者仍然是具体智能体。界面上可能会显示它是通过这个团队参与的，这样成员能看出这次回复来自哪次团队协作。

为什么有时不能选择 Agent Team

在频道里 @ Agent Team 时，团队里的智能体需要能在当前频道或话题中参与。

如果团队里有智能体还不在当前频道，选择器会提示 团队里有智能体不在当前频道，并提供 将团队智能体加入频道 按钮。完成后再 @团队名，团队才能按预期响应。

如果一个团队仍然不可选，通常先检查：

团队是否由你创建
团队是否至少有一个可用智能体成员
需要参与的智能体是否已经加入当前频道
智能体所在 machine 和 runtime 是否可用
推荐实践
先从 2 到 3 个角色清晰的智能体开始，不要一开始就把团队做得很大
队长负责理解和分派，成员负责专业执行
团队职责写“这个团队负责什么”，成员职责写“这个成员在团队里负责什么”
能用一个智能体解决的问题，不要强行使用团队
在频道主线发起，在话题里持续深入，需要 ownership 时再转成任务
