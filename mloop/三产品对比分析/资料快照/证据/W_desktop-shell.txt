# 桌面壳行为守则

> 编号前缀：SHELL ｜ 覆盖范围：窗口与尺寸、托盘、单实例、启动顺序、退出生命周期、自动更新、外部链接、本地数据目录

## 1. 总览

- **SHELL-1｜应用身份（应用标识、产品名、自定义协议、本地数据目录、安装目录）只有一份权威定义。** 公众版与内网版，以及公众版的正式、测试、开发渠道，使用各自的应用身份、数据目录、协议与本机服务端口，可以同时安装和运行。公众版在系统安装与启动入口显示为「MobileWork_公众版」，测试和开发渠道另有对应标记；应用页面、主窗口标题与应用内菜单仍显示「MobileWork」。
- **SHELL-2｜应用区分「用户数据」与「引擎运行数据」两套目录，落点固定、不互相串。** 账号、模型、密钥、技能与默认工作空间属于用户数据，永远读写用户真实的主目录；引擎运行期产生的数据单独存放，开发态隔离到独立目录，安装包形态与用户数据同源。任何一方都不得从被重定向后的主目录去反推另一方的位置。
- **SHELL-3｜同一产品渠道同一时刻只能有一个客户端实例在跑，重复启动会把「这次是谁启动的」交给已在运行的实例。** 第二次启动不会自己开窗、不会自己起引擎，而是直接退出，由已在运行的实例把窗口亮起来、处理带进来的链接，并判断是否需要提示覆盖安装。

## 2. 新增

- **SHELL-39｜开发与安装模式都只在实际配置目录预置当前引擎所需的依赖。** 新建目录不再附带旧引擎及旧工具的兼容依赖；当前原生工具的基础依赖随安装包提供，无需首次执行时临时下载。开发隔离主目录和系统主目录不再额外预置旧引擎依赖；已有个人文件不自动删除。开发运行数据改用产品命名的新目录，模型凭据和调试日志跟随当前账号，公众版残留清理不触及内网版或用户另装的引擎数据。

- **SHELL-4｜首次启动的窗口位置会做「可见性」兜底，而不是照搬上次的坐标。** 没有历史记录时窗口按默认尺寸在主屏可用区域居中打开；上次的位置如果因为换了显示器而完全看不见，会回到主屏居中；只有一部分露在屏幕外时，会被挪回可用区域内、尺寸不变。窗口内容有最小尺寸 860×600，用户再往小拖会被撑住，不会把界面挤坏。右侧栏展开时宽度下限改为 930，高度仍是 600；收起右侧栏后回到 860。展开右侧工作台时窗口会按面板宽度临时加宽，收起后回缩到展开前的宽度，反复开关不会让窗口越变越宽；窗口处于最大化时开关不改变尺寸。
- **SHELL-5｜窗口位置尺寸与「关闭按钮行为」是同一份本地偏好，写不进去也不影响使用。** 移动与缩放会稍后记下来，最小化、最大化、还原则立即记下来；偏好缺失或损坏时回到默认值（关闭按钮＝最小化到托盘）。这份偏好会在处理任何启动链接之前先读出来，保证按上次的窗口状态打开。
- **SHELL-6｜启动分两段：先只做「开窗必需」的事，其余准备工作放到后台并行做，不拖慢首屏。** 与窗口无关的启动内务（专家对账、知识目录、登记表迁移、安全存储日志、启动链接）与开窗并行；后台服务链（网关、界面控制、模型代理、模型投影、MCP 代理）与引擎预热也在开窗前就并行启动。这些并行环节不得依赖主窗口是否已经存在，避免启动顺序被窗口生命周期绑死。需要用到这些准备结果（专家名单、工作区列表、引擎的运行时信息）的后台服务与引擎启动，必须等准备完成后再往下走，否则用户刚打开客户端时可能看到专家缺失或工作区列表不全。
- **SHELL-7｜同时发起的相同启动需求只创建一套服务，健康且配置兼容的服务继续复用。** 失败或被跳过（没有本地工作区、纯远程）的结果不会挡住后续真实启动。已有服务正在恢复时提示稍后重试；工作区配置需要更换服务时给出手动重启入口，不因普通读取或页面切换直接中断已有任务。
- **SHELL-8｜引擎预热可以在窗口出现前就开始，但首次启动不预热。** 只有本机已经有已知工作区时才预热；首次启动交给「登录后创建工作区」的流程自己把引擎拉起来。预热可以用环境变量彻底关掉，关掉的只是预热——登录后仍会真实启动引擎。预热与登录后的启动都等待本地服务就绪，保证签名代理、本地模型投影与 MCP 代理先于引擎起来；云端模型目录在后台加载，通过热更新生效，不占用启动遮罩，也不要求用户重启或刷新。
- **SHELL-35｜会动工作区之外文件的操作，先由系统确认框征得用户同意。** 用系统程序打开路径、在文件管理器中打开目录、在文件夹中显示、把目录交给应用内预览读取，这些操作一旦目标不在已登记的工作区里，客户端都会先弹一张系统确认框，默认选中取消；用户允许后，本会话内同一动作、同一路径不再重复询问。凭据与密钥目录、命令行启动脚本、开机自启目录以及可执行或脚本文件，无论是否在工作区内都直接拒绝，界面按「未完成」提示。已安装技能的「打开文件夹」是例外：主进程按技能安装记录解析出目录后直接打开，不经过这条确认；技能目录不存在或打开失败时按「未完成」提示。
- **SHELL-9｜随客户端分发的必装技能每次启动都会自动同步到最新，用户不需要任何操作。** 内容一致的不重复写；不一致的以客户端内置版本为准覆盖，覆盖过程不会留下半个文件。单个技能同步失败只当作非致命问题，不拦启动。这一步必须在引擎启动之前完成，否则运行中改动被监听的目录会触发一次多余的引擎重载，破坏「引擎只启动一次」的约定。

## 3. 修改

- **SHELL-10｜「关闭按钮行为」是二选一偏好；真正退出时，执行中的任务需要用户确认。** 默认「最小化到托盘」：点关闭按钮只是隐藏窗口（macOS 同时从 Dock 隐藏），客户端继续在后台运行。选「直接退出」时，如果有任务正在执行，会弹出「有任务正在执行中，确认要退出吗?」，说明退出会强制中断任务并可能丢失进度，按钮是「仍然退出」与「取消」；确认框已经在显示时不会重复弹。没有正在执行的任务就直接退出。从托盘选择「退出」时，无论关闭按钮偏好如何，只要有任务正在执行，就先恢复主窗口并显示同一个确认框；取消后任务继续运行。仅有历史对话而没有正在执行的任务时不弹确认。由系统发起的退出仍不拦截。
- **SHELL-11｜覆盖安装后如果旧实例还占着，提示用户重启，而不是替用户杀进程。** 新实例把自己这次的构建身份交给已在运行的实例，后者与它启动时的身份比对，不同才弹「已安装新版本」对话框（「立即重启」与「稍后」，默认立即），确认后自动重启客户端。任一侧身份缺失（开发态没有标记、老版本不带这份信息）就不提示——宁可漏报也不误报；同一时刻只弹一个提示。

## 4. 删除

- **SHELL-28｜含系统沙箱的 Windows 正常卸载及 Linux 系统软件包移除，会先处理沙箱，再删除应用文件。** 覆盖升级保留沙箱；检测到其他受支持安装位置的客户端时保留共享组件并提示。Windows 确认当前环境的沙箱服务、驱动和后台进程均已不存在时，可以直接卸载客户端；供方仅报告文件清理不完整，且上述活动组件均已不存在时，也继续卸载客户端，并提示仍有文件残留。授权取消、其他供方错误或无法确认活动组件已移除时，保留应用文件供重试。共享检测不能覆盖其他账户的私有安装、未登记客户端或任意位置的独立应用镜像；独立应用镜像直接删文件不会触发联动卸载。Windows 与 Linux 的正式版、测试版沙箱分别交付，卸载只操作当前环境的服务与驱动；同环境其他安装仍会阻止共享组件卸载，另一环境不阻止。无法确认身份的旧安装仍保守保留。

- **SHELL-12｜退出是一条固定的五段流程：运行中 → 等待确认 → 正在退出 → 正在释放资源 → 已退出。** 「等待确认」阶段在内部仍被视为运行中，正是靠这一点关闭拦截才生效；没有在等确认时收到的关闭应答一律忽略；第二个退出信号可以从任何阶段直接强退到已退出。
- **SHELL-13｜退出时先显示一张深色的「正在关闭」画面，再停掉本地服务，停不掉也照常退出。** 画面文案是「正在关闭 MobileWork 服务」与「正在停止本地任务与后台服务…」；随后并行停止运行时、界面控制、浏览器自动化网关、模型代理、MCP 代理以及预览资源，最后才真正销毁窗口。释放过程中的异常不阻断退出，重复的释放请求只执行一次。窗口状态持久化在释放之后执行。
- **SHELL-14｜收到系统退出信号与「窗口全部关闭」是两条不同的收口。** 系统退出信号不做默认强杀——那会把引擎与服务端进程留成孤儿——而是走正常退出流程把本地服务释放干净；释放卡住时再来一次信号会直接强退。窗口全部关闭时先销毁浏览器视图与窗口：非 macOS 直接退出客户端；macOS 保留进程，用户点程序坞图标时重建窗口，但登录隐藏启动期间点图标不会把窗口亮出来。

## 5. 生效与状态

- **SHELL-15｜客户端不会自动安装更新，只会把安装包交给用户手动完成。** 更新流程固定为检查、下载、校验、已就绪四步，任一步失败都回到可重新检查的失败态。Windows 上会登记「客户端退出后自动启动安装包」，登记成功后客户端退出；macOS 与 Linux 上则打开安装包所在文件夹，由用户自行安装，交接完成后同样退出客户端，避免占用安装进程。
- **SHELL-16｜自动检查更新的触发点是「界面启动就绪」，不在客户端启动时立刻跑。** 界面在登录成功且所有工作区加载完成后发一次信号，这次检查是异步的、不把结果回给界面。此后会定期自动再检查一次；正在检查、正在下载、正在校验或已经下载好时不重复触发，只有空闲与上次失败才继续。检查时机在登录后重新起算，单次检查失败只记日志、不影响其它功能。
- **SHELL-17｜强制更新分两步：先弹「发现新版本」，用户点「去更新」才开始下载。** 只发现强制更新时不会偷偷下载，但界面会保留目标版本、更新内容等强更信息，据此弹出不可关闭的弹窗；只有用户确认后才走正常下载流程。等待确认期间如果下载名额已满，弹窗不会闪断或消失，强更信息仍然保留；服务端随后撤回这个版本时，残留的强更信息会被清掉，弹窗也不再出现。
- **SHELL-18｜已经下载好的安装包不会重复下载，重启客户端后仍显示已就绪。** 本机已有同一个目标版本、文件校验一致且文件还在时，仍然会向服务端确认一次有没有更新，但跳过下载直接进入已就绪；重启客户端后也能从本机记录恢复成已就绪（含版本号、更新日志、是否强制与内测版标注）。如果目标版本不比当前已安装的版本新（例如用户已经通过其他途径升到更高版本），重启后不再恢复这个旧安装包，也不会提示安装；目标版本变了、文件校验不一致或安装包被删掉，都当作没有下载过，重新下载。
- **SHELL-19｜安装包在本机的位置是固定的两层目录，旧布局会在启动时后台清掉。** 公众版和内网版、不同环境各有自己的目录，启动时只清本产品本环境的旧布局，同时装着的另一个环境的数据不会被误删。清理失败只记日志、不影响使用；主目录缺失或环境取值不在已知范围内时一律跳过清理，绝不误删整个旧目录。
- **SHELL-33｜更新安装包在本机只保留最新一版，历史版本不再逐版积累。** 每轮更新下载成功（或确认本地已有同版本安装包跳过下载）后，自动清掉安装包目录下其余版本的内容，只留最新这一版供安装；下载或校验失败时不清理，此前已下载的安装包仍然保留。清理只删本环境安装包目录下的版本子目录，更新记录目录与其他文件不动；清理失败只记日志，不影响更新流程。
- **SHELL-27｜升级就绪提示的标题按发布类型区分：普通发布是「新版本更新就绪」，内测版发布是「新版本（内测版）更新就绪」。** 只有服务端把这轮版本明确标注为「内测专用」时才用内测标题；同时面向内测与普通的版本、以及没带发布类型的旧服务端响应，都按普通标题显示，绝不把普通用户拿到的升级说成内测版。服务端撤回这个版本时残留的内测标注一并清掉；重启客户端后从本机记录恢复的已就绪提示仍保留内测标注。强制更新弹窗标题不受此影响（仍是「发现新版本」）。
- **SHELL-36｜安装包只从预设的下载域名下载，清单里出现其他地址时不会下载。** 检查更新时云端会给出安装包下载地址；客户端只接受与更新服务同源的主机，或随安装包按环境预设好的域名清单里的主机。清单里出现其他主机、或地址根本不是完整的网页地址时，这一轮更新直接按失败处理：不写下载记录、不探测、不下载、不占云端名额，也不弹强制更新弹窗。预设清单随安装包按环境烘焙，条目不写端口表示该主机任意端口都可以；不支持通配符。

## 6. 可见性与入口

- **SHELL-37｜macOS 顶部菜单跟随系统首选语言。** 支持简体中文、繁体中文与英文，按系统语言列表顺序选择第一个支持的语言，均不支持时显示英文；更改系统语言后重启客户端生效。应用内界面的语言设置不改变顶部菜单，菜单原有操作与快捷键保持一致。

- **SHELL-20｜托盘只有一个，菜单是「显示主窗口」与「退出」，单击图标也能把窗口亮出来。** 选择「最小化到托盘」或本次由开机登录隐藏启动时会预建托盘。托盘建不出来时（例如取不到图标），关闭按钮的拦截会退化为不拦截——窗口被真正关掉，而不是变成一个关不掉的窗口。托盘里的「退出」与关闭按钮走同一套退出意图。
- **SHELL-21｜开机启动拉起的是后台服务，不是主窗口。** Windows 与 Linux 上看启动参数判断这次是不是登录拉起，是的话隐藏窗口、只留托盘作为入口；macOS 认系统的「登录时打开」标记，并为老系统额外请求隐藏打开。Linux 会自己写一份开机自启配置（必须写在系统用户的真实主目录，不能用被重定向过的目录），可执行文件路径含空格时会加引号；配置里被标成隐藏或禁用就视为已关闭。未打包运行时不允许注册开机启动，界面提示「开机启动仅在安装后的桌面客户端中可用。」
- **SHELL-22｜「钉到桌面」一个组件一个窗口，重复钉只把已有窗口聚焦，不再开一个。** 小窗无边框、默认置顶，多个小窗之间按级联偏移摆放，避免完全重叠；窗口上的置顶切换与取消固定由界面自己绘制。小窗尺寸由右下角的自绘把手拖拽调整（无边框窗口在 Linux 下没有系统缩放边框），拖到比 360×420 更小会被撑住。小窗只承载组件内容：不跑主窗口的启动引导，也不显示「正在准备」启动遮罩。窗口操作（关闭、置顶、缩放）只作用于发起操作的那个小窗，钉住窗不能去操作别的窗口，也不接受界面传进来的窗口标识。macOS 上小窗在所有工作区与全屏下都可见，Linux 上固定在所有虚拟桌面，Windows 上不做跨桌面处理。
- **SHELL-23｜外部链接只处理登录回调，其它链接不再进入应用；登录结果缓冲到窗口就绪再投递。** macOS 从系统接收链接，其它平台从第二次启动的参数里拿；只有属于统一身份登录回调的链接会交给登录流程，其它自定义协议与网页链接一律忽略，不再排队或分发到界面。登录结果在窗口还没准备好时先缓冲，窗口可以显示时补投；登录回调完成后会主动把主窗口拉到前台——此时浏览器还在前台，不主动拉一下焦点就回不来。
- **SHELL-34｜向外打开链接只认网页链接与邮件链接，其他协议一律不打开。** 在应用界面里点网页链接交给系统默认浏览器，点邮件链接交给系统默认邮件程序；本地文件、共享盘、以其他应用协议开头的链接不会被打开，也不会拉起本机对应程序，只在主日志里留一条安全记录。被拒绝时界面不弹提示，用户的感觉是点了没有反应。浏览器面板里网页内容自己的弹窗仍只把邮件链接交给系统，其余网页链接留在内置浏览器里打开。账号相关页面在打开前还会核对目标站是否属于当前环境配置的门户站点，不属于就不打开、也不会把登录凭证带到该地址。

## 7. 失败与边界

- **SHELL-40｜启动失败后的普通重试只继续失败阶段，保留当前页面与草稿。** 连接通知不会另起一条互相干扰的启动流程；明确选择重启服务仍会执行真正的重启。启动完成后的恢复按原规则刷新，迟到的旧请求不能清掉当前错误。

- **SHELL-24｜安装包形态可以整体禁用开发者工具，相关快捷键也一并失效。** 这项限制由打包配置或环境变量开启，开启后窗口根本不带开发者工具，菜单入口与 F12 都不可用，打开开发者工具的常用快捷键组合也会被吞掉，不会留下半个能用的入口。开发态（未打包）会把窗口标题固定成产品名，不让页面标题改写它。
- **SHELL-25｜已知缺口（未修）：必装系统技能的启动同步一旦失败，同一个进程内不会再重试，必须重启客户端。** 这与引擎启动「失败不留缓存」的口径不一致：用户在本次运行中无论怎么重试、怎么新建工作区，缺失的必装技能都不会补上，只能重启应用。修法应在启动引导这一层（失败时清掉这次结果，与引擎启动同一口径），而不是在各个调用点补重试。
- **SHELL-26｜已知缺口（未修）：开发态下正式环境与测试环境共用同一个更新恢复目录。** 两个环境的事务记录与同版本安装包目录会互相覆盖：最坏情况是多下载一次安装包；如果服务端下发的清单里没有校验值，界面甚至可能把另一个环境的安装包当成自己的交给用户。这只影响本机联调，不影响发布版本；修法应在恢复目录的推导处把开发态的两个环境区分开，而不是在下载链路上补救。

- **SHELL-29｜本机调试服务被其他实例占用时，不会终止占用进程。** 当前实例提示对应能力暂不可用；端口释放后可以重新启动，其他应用和任务不受影响。

- **SHELL-30｜测试版和正式版使用各自的引擎身份，不混用其他产品或环境的沙箱。** 构建环境自动决定引擎所连接的对应服务，无需用户额外配置；对应沙箱服务未就绪时明确停止启动，不能静默连接其他环境的服务。
- **SHELL-32｜账号私有目录和敏感文件只允许当前系统用户访问。** 本应用创建或升级的账号私有目录只开放给当前系统用户，密钥、敏感配置及其临时文件只开放当前用户读写；不会递归修改用户工作区、共享盘或系统目录的权限。这些权限用于隔离不同系统用户，不能区分同一系统用户下的不同 MobileWork 账号。

- **SHELL-31｜Windows 覆盖安装清理本安装的后台进程时，保留安装器自身及启动它的进程链。** 旧版本卸载失败时明确提示卸载失败和退出码，不把所有失败都解释为客户端未关闭；不能完成旧版本卸载时停止覆盖，保留恢复机会。

- **SHELL-38｜自动上报到运维平台的链路与事件记录会遮盖手机号、邮箱和银行卡号。** 手机号保留前三位和后四位供排障检索，可能与其他人重复；用户名与脱敏手机号用于关联当前账号的记录。未登录时不伪造账号，换号后新记录使用新账号，已经开始的请求仍归原账号；脱敏不改变实际业务内容，也不改变意见反馈附件的处理方式。安全检测请求保留脱敏后的实际发送参数供排查，不附加未发送的历史内容或登录凭证。主任务与子任务（包括后台记忆整理）均保留本轮输入的脱敏记录。主任务与子任务的模型回复按最终正文记录，逐步显示过程中重复收到的内容不会被再次拼接，回复本身包含的重复文字仍保留。同一轮对话不会因同时打开多个任务而重复上报为多条独立链路或重复累计用量，子任务仍关联到所属主任务。

## 8. 禁止事项

- 不得另写一份应用身份（应用标识、协议、数据目录），也不得让测试版与正式版共用应用标识或数据目录（见 SHELL-1）。
- 不得让持久化数据从被重定向后的主目录重新推导用户数据路径，也不得把专家源包写进用户数据目录（见 SHELL-2）。
- 不得让第二个实例自己开窗或起引擎，也不得在覆盖安装提示里自动杀掉旧进程（见 SHELL-3、SHELL-11）。
- 不得把新增启动项塞进「开窗必需」的串行段，也不得让内务链、后台服务链或引擎预热依赖主窗口（见 SHELL-6）。
- 不得把引擎启动的失败或被跳过结果缓存下来（会让重试与新建工作区点不亮引擎，见 SHELL-7）。
- 不得在引擎启动之前跳过必装技能同步，也不得把这次同步拖到监听启动之后（见 SHELL-9）。
- 不得把「等待用户确认退出」这一阶段当成已经在退出（会让关闭拦截失效，见 SHELL-12）。
- 不得把自动检查挪到客户端启动时执行，或绕过「界面启动就绪」这个唯一入口（见 SHELL-16）。
- 不得让客户端自动安装更新，也不得在未登记或未打开安装包之前就退出客户端（见 SHELL-15）。
- 不得在强制更新「发现即停」阶段就写记录或开始下载（见 SHELL-17）。
- 不得在清理旧更新目录时删掉并存环境的目录，也不得在环境取值非法时回落到旧目录（见 SHELL-19）。
- 不得在下载或校验失败时清理已下载的安装包，也不得让版本目录清理波及更新记录目录或非版本内容（见 SHELL-33）。
- 不得把「内测和普通」或没带发布类型的版本标成内测版，也不得让内测标注残留在服务端已撤回的版本上（见 SHELL-27）。
- 不得绕过预设的下载域名清单去下载清单外的安装包地址，也不得把这道校验放到写下载记录之后（见 SHELL-36）。
- 不得让托盘创建失败时的关闭行为变成「关不掉的窗口」，也不得让登录隐藏启动没有亮窗入口（见 SHELL-20、SHELL-21）。
- 不得给钉住的小窗增加「按界面传来的窗口标识操作别的窗口」的路径（见 SHELL-22）。
- 不得把本地文件、共享盘或以其他应用协议开头的链接交给系统默认程序打开，也不得让某一条打开入口绕过这条限制；账号相关页面不得把登录凭证带到当前环境未配置的门户站点（见 SHELL-34）。
