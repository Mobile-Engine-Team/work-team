# 模型与服务商行为守则

> 编号前缀：MODEL ｜ 覆盖范围：模型选择与默认、模型就绪与重试、模型目录与服务商授权、额度与 token 上限

## 1. 总览

- **MODEL-1｜一个模型的身份由「服务商 + 模型」共同决定，全链路只有这一种表示。** 说明：保存、传输和比较都按这一对来；比较时不能只比模型名或展示名，不同服务商下的同名模型是两个不同的模型。
- **MODEL-2｜「自动」是一个本机别名模型，只在桌面端且本地工作区可用。** 说明：远程工作区和网页端不提供「自动」选项，候选列表里会把它去掉。
- **MODEL-3｜「自动」指向哪个模型由模型目录里的解析目标决定，从不按模型名猜。** 说明：目录里没有「自动」条目、该条目未启用，或它不是走签名代理通道时，「自动」就没有目标，界面按不可用处理。
- **MODEL-4｜选不到模型时按固定顺序回退：工作区已选 → 全局默认 → MobileWork 产品默认 → 引擎默认 → 选项里的第一个。** 说明：不在当前工作区可用范围内的候选一律跳过，这样桌面端专属的默认值不会泄漏到远程工作区。
- **MODEL-5｜后台任务与无界面运行取模型的口径统一：优先用工作区已选模型，没有就回退全局默认。** 说明：两个来源都落到那条走不通的通道时改用产品默认，避免后台任务用一个连不通的模型；从没打开过、没有保存记录的工作区按「没有」处理，继续回退。自动化任务显式选「自动」时不走这条口径，按本文件的「自动」规则执行（见 MODEL-2、MODEL-3）；自动化选不了「自动」时（远程工作空间或本机没有可用入口）仍按这条口径回退，且候选必须出现在当前可用的模型目录里。

- **MODEL-36｜官方模型与自定义模型的 MAF 审核默认关闭。** 新账号、新增自定义模型和历史配置中未设置的审核开关均按关闭处理；用户已保存的开启或关闭选择继续生效，官方总开关不替代自定义模型自己的选择。

## 2. 新增

- **MODEL-6｜新增自定义模型时，可以只填输入或输出 token 上限，没填的优先采用该模型已知规格，没有已知规格时按 256K 总上下文、32K 输出补齐。** 说明：自定义模型填写的输入上限代表总上下文窗口；上限必须是大于 0 的整数，非法输入提示「请输入大于 0 的整数 token 数。」；只填其中一个上限同样生效，已填写的值不被默认值覆盖。官方模型目录缺少输入或输出额度时，缺失项分别按 224K 输入、32K 输出补齐；输出缺失且默认输出不小于输入额度时沿用旧默认 8K，再按原有规则校验。两项都缺失时总上下文为 256K，云端已返回的额度不被覆盖。
- **MODEL-7｜本地配置文件弹窗只编辑用户自建的模型，内置模型定义不由用户改。** 说明：弹窗里不会显示诱导误改的内置标记；但保存时必须带上完整的列表（含内置项），否则用户此前关掉的内置模型会自己弹回来。
- **MODEL-8｜开发版和安装版默认提供自定义模型配置入口。** 说明：可通过部署配置关闭新增、编辑入口；关闭后已保存的自定义模型仍可查看、选择、启停和删除，重新开放后恢复新增、编辑。

## 3. 修改

- **MODEL-9｜远端目录有实际变化时热更新模型，不重新加载工作区。** 引擎确认配置更新后刷新界面列表；没有变化时保留现有列表与运行中的会话。
- **MODEL-10｜token 上限也算模型配置的一部分：只改了上限同样会被识别为配置变化并刷新缓存。** 说明：没填上限的模型不受影响；上限值相同、只是填写先后不同，不会被当成变化。
- **MODEL-11｜模型选择器按服务商分组；桌面端合成的展示名要拆开再分组。** 说明：合成展示名形如「MOMA系列 · 九天236B-测试」（系列 · 模型）；整串当成服务商名会让同一系列下每个模型各自成一个「某某系列」分组。拆分规则与引擎投影保持一致。
- **MODEL-12｜打开模型选择器会刷新当前账号可见的远端目录（内容没变则保持当前列表）；已隐藏的旧选择保留原来的标签，刷新失败也不会丢掉保存过的标签。** 说明：远端功能描述只挂在官方或云目录条目上，本地模型不显示特性副标题。
- **MODEL-31｜模型实际可用的最大输出长度按该模型配置的输出上限生效，不再被一个全局固定上限压到 32K。** 说明：云端目录或自定义模型里配置的输出上限超过 32K 时，按配置的值生效；配得较小或未单独配置的模型不受影响，仍按较小的值执行。

## 4. 删除

- **MODEL-13｜目录里已下架的模型，即使运行时还列着也不能选。** 说明：定时核对只发生在自动化任务列表打开且窗口可见时。首页会话在每次新建任务或打开模型框时核对一次：目录有变化就更新列表，没变化列表保持原样，中间不闪加载页。选择器还会隐藏「自动」实际指向的那条重复项，但只在「自动」入口可用时才隐藏；自定义模型和其他非目标模型一律保留。
- **MODEL-14｜已保存的模型被下架后，界面不静默替换，而是保留这个选择并标为不可用。** 说明：只有本次草稿里用户没显式选过模型的首次发送才做静默降级；历史任务和新建任务草稿保留原选择，允许继续输入；工具栏显示带红框的「请选择模型」，发送按钮置灰，点击发送区域或按发送快捷键时提示「当前模型已下架，请重新选择模型」。重新选择可用模型后，草稿保留且恢复发送。

## 5. 生效与状态

- **MODEL-15｜模型就绪有 6 种状态：加载中、重试中、就绪、未配置、需要认证、连不上。** 说明：失败会自动重试，最多 5 次；重试期间界面显示「模型暂不可用 · X 秒后尝试第 N/M 次」或「模型暂不可用 · 正在尝试第 N/M 次…」，让用户知道还要等多久、已经是第几次。
- **MODEL-16｜模型准备分为本机目录展示和发送前的引擎核对。** 启动和登录完成不等待云端模型目录；用户可先进入应用、查看任务和编辑草稿，模型准备好后发送。只看本机配置的就绪不能代替发送前核对；远端工作区始终使用自己的模型运行时。
- **MODEL-17｜同一工作区的两种准备请求各自去重。** 本机目录读取不能抢占、取消或覆盖引擎核对；连接恢复保留正在准备的请求，配置变化使旧结果失效。
- **MODEL-18｜运行中的会话不因模型配置变化而中断。** 新增、修改、启停和删除模型通过热更新生效；已发出的请求沿用当时的配置，新会话和旧会话的下一轮使用更新后的配置。不会在当前回复中途强行切换模型。
- **MODEL-19｜模型投影失败或引擎尚未读到所需模型时如实提示不可用，不误报就绪。** 用户填写的地址、凭据和 token 上限统一由模型配置保存流程投影。
- **MODEL-20｜只看本机配置这一路读到的官方或云端模型，凭据在界面上本来就是看不到的，这不影响它们正常展示。** 说明：官方与云目录条目的凭据只存在于主进程，MoMA 类条目更是只有登录态、本就没有静态凭据；界面看不到凭据不等于模型不可用。
- **MODEL-33｜首页深度洞察的四个专家团使用「自动」时，候选模型清单可由云端下发。** 说明：深度研究、智慧巡察、财经专家、商品推荐四个专家团按云端下发的清单在「自动」中选模型；客户端启动或登录后获取一次，可重试失败会静默重试，仍失败就继续使用内置清单，不阻断使用。失败后每次用这四个专家团发消息前会再尝试一次，成功后本次启动期间不再重复获取。其他对话场景的「自动」候选清单不受影响。

## 6. 可见性与入口

- **MODEL-21｜模型不可用时，用户能看到具体原因和对应出口，而不是一句「加载失败」。** 说明：文案分四档——需要认证时「模型 Provider 需要重新认证。」；连接凭据无效或已过期时「工作空间连接凭据无效或已过期。」；连不上时「无法连接此工作空间的模型运行时。」；没有配置时「此工作空间尚未配置模型 Provider。」。动作按钮按场景给「立即重试」「打开模型设置」「编辑连接」「重新认证 Provider」「查看远程配置说明」。
- **MODEL-22｜显示「请选择模型」时仍可编辑草稿，但不能发送。** 说明：模型入口的红框、灰色发送按钮与点击气泡见 MODEL-14。
- **MODEL-23｜来自引擎的模型目录只列出已连接的服务商。** 说明：云托管的那条产品自有服务商从已连接列表里统一剔除，避免列表里出现一堆还需要登录的模型；本机配置补充的模型见 MODEL-32。
- **MODEL-24｜模型列表有短时缓存；就绪热路径只取「已连接 + 自定义」这部分模型。** 说明：这部分数据不会写进全量目录的共享缓存，独立模型选择器、知识库的模型选择和设置页仍然读全量；这部分数据里的模型信息不会被裁剪，能力标记、行为档位与附件直传判定照常可用。
- **MODEL-25｜VIP 用户的「自动」优先取目录里标记为 VIP 的模型；三个模型选择入口都会隐藏「自动」实际指向的那条，VIP 还额外隐藏官方的自动编码模型。** 说明：底层服务商和旧任务里已有的引用都保留，不会被清掉。
- **MODEL-34｜红名单用户登录后会看到目录里标记为红名单的模型；红名单与 VIP 相互独立，也不改变「自动」的选择。** 说明：目录按登录身份返回普通模型加红名单模型；红名单不参与排序、不进入「自动」的优先候选，红名单身份本身不带来 VIP 模型。登录用户信息里还没有红名单字段的环境按非红名单处理，这些用户看到的模型列表不变。
- **MODEL-32｜本地工作区的聊天模型选择器可展示本机已明确配置并保存对应认证信息的 OpenAI 与 Zhipu AI Coding Plan 模型。** 说明：列表只展示模型信息，不展示凭据；能看到模型不代表当前认证有效或模型调用已经验证，发送前仍按既有模型就绪流程核对。

## 7. 失败与边界

- **MODEL-26｜服务商认证错误分四类，各有判据。** 说明：401 与 403 归为「连接凭据无效」；错误措辞里出现未授权、禁止、认证、密钥、令牌等字样归为「服务商需要认证」；提示没有模型、服务商未配置的归为「未配置」；其余归为「连不上」。这套分类只看状态码和措辞，不区分 401 的具体成因——上游网关的瞬时 401（票据轮换、短时过期、限流误报）同样按「工作空间连接凭据无效或已过期。」呈现（见 MODEL-21）；按可恢复性细分 401 只做在会话错误卡上（见 MODEL-27），不在这个分类里。
- **MODEL-27｜会话错误卡必须保留原始诊断信息（追踪号、原因码、诊断描述，经脱敏处理），不能只剩错误码和时间。** 说明：丢掉原始错误会让用户复制出的诊断报告里除错误码和时间外全是空，现场无法判断是哪一类 401。
- **MODEL-28｜读取服务商列表不会无限期等待，超时按失败走既有的有界重试。** 说明：引擎冷启动或被别的子任务拖住时，这次读取可能一直不出结果；没有这道兜底会把模型就绪流程挂死在一次尝试上。
- **MODEL-29｜模型列表为空时区分「没配」和「没连」：条目里有模型但一个都没连上，是「需要认证」；连有模型的服务商都没有，是「未配置」。** 说明：两种情况对应不同的引导文案与出口。
- **MODEL-30｜本机没有可展示的模型时，只看本机配置的那一路直接给终态、不会一直重试，由横幅引导用户去设置页。** 说明：这与向引擎核对那一路的「失败后重试」语义不同。

- **MODEL-35｜自建模型与模型审核开关按登录账号隔离。** 换号后只展示、使用当前账号配置的自建模型；切回原账号恢复其配置，修改或删除不影响其他账号。无法确认归属的历史共享配置不会自动归给任一账号。

## 8. 禁止事项

- 不得按模型名或展示名推断「自动」的目标（见 MODEL-3）。
- 不得只比模型名，或在界面里另建一套模型回退顺序（见 MODEL-1、MODEL-4、MODEL-5）。
- 不得把「只看本机配置」的就绪当成引擎已验证，也不得让它抢占正在进行中的核对请求（见 MODEL-16、MODEL-17）。
- 不得为了使模型配置生效而中断会话或重载工作区（见 MODEL-18）。
- 不得在目录没有变化时重新加载工作区（见 MODEL-9）。
- 不得让已下架的模型仍出现在选择器里（见 MODEL-13）。
- 不得在模型下架后静默替换用户已保存的选择；草稿必须显式标为不可用（见 MODEL-14）。
- 不得因为界面上看不到凭据就把官方或云模型判为不可用（见 MODEL-20）。
- 不得把服务商的原始错误文本直接展示给用户，也不得丢弃追踪号、原因码与诊断描述（见 MODEL-26、MODEL-27）。
- 不得按合成展示名给模型选择器分组（见 MODEL-11）。
- 不得把「已连接 + 自定义」这部分数据写进全量目录的共享缓存（见 MODEL-24）。
- 不得把 token 上限从模型配置变化的判定里去掉（见 MODEL-10）。
- 不得让模型配置的输出上限被一个全局固定值截断而不生效（见 MODEL-31）。
- 不得让云端下发的候选模型清单作用到首页深度洞察四个专家团之外的对话（见 MODEL-33）。

## 失效条目

（无）
