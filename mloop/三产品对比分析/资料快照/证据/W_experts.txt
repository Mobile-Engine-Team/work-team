# 专家模块行为守则

> 编号前缀：EXP ｜ 覆盖范围：专家与专家团的来源、安装与召唤、卸载、生效状态与各入口可见性

## 1. 总览

- **EXP-1｜专家是全局资产，不属于任何工作区。** 装一个专家就对所有空间生效；不存在「只在某个空间装了某专家」这种状态，卸载同理。
- **EXP-2｜专家有三个来源，装进来之后不再区分出身。** 云端市场下载的、客户端自带的、自己创建的，都进同一份专家清单；形态只有「专家」和「专家团」两种，专家团是多成员。
- **EXP-3｜「已安装」以实际装好的专家为准，列表只是它的展示。** 两者不一致时以实际为准；每次启动会自检一次并修好差异，不会反过来改实际内容去迁就列表。
- **EXP-4｜一个专家就是一个能被指派干活的智能体；专家团是主智能体带成员。** 召唤专家团时由它的主智能体带队，成员在被委派时参与。
- **EXP-5｜没有被召唤过、或已经卸载的专家，别的智能体不能调用它。** 这道闸门是全局的、跟具体空间无关；召唤或卸载专家都不需要改动某个空间的设置。

## 2. 新增

- **EXP-6｜召唤只是「选中并预填」，不是立刻开工。** 在专家卡、我的专家列表或首页入口点召唤后，这个选择会被记住（切走再回来还在），并跳到任务页预填示例提示词；真正的安装与切换发生在你下一次发送之前。
- **EXP-7｜召唤一个还没装的专家，会自动装好再用。** 同一次召唤不会重复下载或重复安装。
- **EXP-8｜召唤一个专家，对所有空间都生效。** 不需要在别的空间再召唤一次；忙时默认等任务结束后生效，只有用户明确确认立即终止并生效时才可以打断。
- **EXP-9｜客户端自带的专家被召唤或安装后，与云端装来的专家同等对待。** 可以升级、可以卸载，不再只是只读的附带内容。
- **EXP-10｜自己创建的专家留在本地统一存放，不往各个空间里塞副本。** 可以直接在“我的专家”所在文件夹中创建。
- **EXP-11｜内置资源版本落后时，发送前会多一步「下载最新资源」。** 版本一致、检查失败或本次没用到内置资源时，流程与原先完全一样；某个资源下载失败会重试一次，仍失败就提示「已使用本地版本继续」，不会卡住这次任务，本次会话也不再重试。
- **EXP-33｜没有安装 Git 也能创建、修改、导入、校验、安装和打包自己的专家。** Git 仅用于本地版本历史、提交、标签和基于历史的版本建议；未安装时正常交付专家，不要求用户为普通操作安装 Git，也不催促发布版本。补装后可在下一次实际修改或首次明确确认发布时启用，只记录启用后的历史。

## 3. 修改

- **EXP-12｜从「我的专家」或输入框的专家浮层召唤同一个专家，得到的是同一个专家身份。** 专家工作区的市场卡走的是另一条链路（没装就先下载安装），两条链路必须给出同一个身份，否则同一个专家在不同入口会被当成两个包。
- **EXP-13｜同一个专家如果既有自带版本也装过云端版本，不并存两份。** 云端那份更新时就用云端那份。
- **EXP-14｜新专家的标识或工具名和已有内容撞车时，跳过并告警。** 不会把已有专家顶掉或抢占。

## 4. 删除

- **EXP-15｜有任务在跑时不允许卸载专家。** 会明确告诉你哪个空间正在跑；全部空闲才弹确认框，确认框列出会受影响的空间。
- **EXP-16｜卸载成功后，各处的专家列表都会更新，统计数据里也不再以这个专家的身份出现。** 否则以后同名的另一个专家会被算成它。
- **EXP-17｜自己创建的专家没有「卸载」入口，删除在「我的专家」里做。** 对这类专家调用卸载只会得到错误。
- **EXP-18｜每次启动会自检一次专家存放。** 会清掉装了一半的残留、把没登记的收编进来、删掉多余的副本、把被改动过的专家内容恢复回来；删除过的专家也不会留下永久生效的禁用记录。自检失败只提示，不影响启动。

## 5. 生效与状态

- **EXP-19｜召唤默认不会打断正在跑的任务。** 忙的时候询问如何生效；选择稍后时召唤可以完成，但尚未生效的专家不能被选来发送。用户明确选择立即终止并生效时，才会中断相关任务。
- **EXP-20｜如果专家已经作为可交互的主智能体可用，召唤时不会再触发一次重新加载。** 不弹窗、不卡顿。
- **EXP-21｜在弹窗里点「取消」＝这次召唤中止。** 不会重新加载，也不会排队悄悄生效。
- **EXP-22｜专家的增删统一按「稍后生效」通知所有空间。** 只有少数链路（例如发送前的预装）会立即生效，但它们同样会先确认没有任务在跑，撞上运行中的任务时直接提示稍后重试，不会打断任务。
- **EXP-23｜重新加载既没成功也没排上队时，召唤明确失败并给出提示。** 不会假装成功。

## 6. 可见性与入口

- **EXP-24｜卸载会清理当前选择，但保留最近召唤历史。** 草稿、会话及未发送召唤中的选中残留会清理；最近召唤记录不因本机卸载而删除，展示时按本机已安装或市场仍在架的可用性过滤，离线无法核实时不贸然删掉历史。
- **EXP-25｜自动化的「召唤专家」浮层交互与新建任务同口径（合并专家与本机已组装数智员工、可按名称搜索），但最近召唤列表彼此独立。** 市场资产专家选中后执行时按需装包；数智员工（含市场「手动创建」）已在本机组装完成，执行只注入人设、不再装包。判断「是否已装」不能只看这个浮层。
- **EXP-26｜专家使用统计按资产的身份上报（资产编号与资产名），不用内部智能体标识。** 自带专家没有资产编号时用包名兜底，否则它在统计里永远不会出现。
- **EXP-35｜输入框与自动化创建弹窗都只有一个「专家」召唤入口，最近召唤同时包含专家和数智员工。** 「个人专家」与「专家市场」分别从浮层底部的「召唤个人专家」「召唤其他专家」进入；最近召唤最多显示 3 条，悬停展示能力介绍。

- **EXP-37｜公众版不再提供流程录制能力，也不展示对应的内置或已安装专家入口。** 历史个人专家文件、录制产物及会话不会自动删除；其他专家、语音输入和浏览器操作保持原有能力。

## 7. 失败与边界

- **EXP-27｜卸载失败会有明确提示，不会假成功。** 文件类错误提示专家文件操作失败；找不到该专家时提示刷新；未知错误给出通用失败提示，并且不触发重新加载。
- **EXP-28｜卸载后的清理是尽力而为。** 包已经卸载成功时，清理统计身份失败不改变卸载结果；卸载失败时统计身份保持原样（包还在）。

- **EXP-34｜专家文件修改与本地版本管理分别如实报告。** Git 缺失不影响已完成的普通修改；Git 存在但仓库异常或初始化失败时，要说明文件是否已经修改及版本管理未完成，不能假装全部成功或完全未修改。已有历史、覆盖确认和并发冲突保护始终保留；版本提交和标签仍需用户明确授权。

## 8. 禁止事项

- 不得未经用户明确确认，在召唤或卸载时打断正在跑的任务（见 EXP-19、EXP-22）。
- 不得把用户点的「取消」当成「稍后」（见 EXP-21）。
- 不得把「既没成功也没排队」说成成功（见 EXP-23）。
- 不得把专家做成工作区级资产，或为某个空间单独装一个专家（见 EXP-1）。
- 不得让召唤只在当前空间生效（见 EXP-8）。
- 不得让没召唤的专家被别的智能体调用，也不得把这道闸门下放到单个空间（见 EXP-5）。
- 不得在卸载流程里跳过清理统计身份（见 EXP-16）。
- 不得给自己创建的专家加卸载入口，或用「卸载」实现「我的专家」的删除（见 EXP-17）。
- 不得用内部智能体标识顶替资产身份做统计上报（见 EXP-26）。
- 不得在输入框保留第二个数智员工召唤入口，也不得把最近召唤拆成两份列表（见 EXP-35）。
- 不得在实际安装与专家列表不一致时改实际内容去迁就列表（见 EXP-3）。

- 不得因未安装 Git 阻止普通专家交付，也不得把缺少版本管理说成待发布或已发布（见 EXP-33）。
- 不得吞掉真实仓库错误、伪造历史，或把只读版本预览当作建仓及发布授权（见 EXP-34）。

## 失效条目

以下条目于 2026-11-02 失效：公众版彻底移除流程录制能力，现行范围见 EXP-37。

- **EXP-29｜流程录制开放 Windows x64 与统信 UOS 的 x86 架构 64 位系统 的 X11 桌面，其他系统仍可看到已安装的流程录制专家。** 统信需能确认系统身份、桌面会话和显示连接，且录制依赖与设备权限就绪；其他 Linux 发行版、32 位系统、ARM64、macOS、Wayland 和 XWayland 暂不支持。条件不满足时，开始、停止和状态查询均明确提示不支持的系统或未满足的条件，不会启动录制器。
- **EXP-36｜替换录制器内部程序时，不需要维持旧文件名、模块列表或旧清单。** 客户端只检查自己启动所需的位置及安全文件操作条件，不预先保证供应程序兼容或复制内容完全一致；真正缺少依赖、进程退出或服务未就绪仍明确失败。替换前应结束录制并等待相关进程退出，正在录制的会话不切换现用包。来源改名、增删、大小或修改时间变化会触发新包；同长度且保留修改时间的编辑须显式目录导入，重启不强制刷新。升级迁移保留原有选择和编辑，不自动用当前源码覆盖现用包。
- **EXP-30｜录制器新候选准备失败时，可以继续使用经过复查的现用版本。** 现用版本必须仍可运行，原有选择、待启用版本和回滚选择全部保持；不能把失败候选说成更新成功。用户取消、必要运行资源尚未解压就绪、选择状态无法读取或保存、现用版本本身不可用时，仍明确失败。
- **EXP-31｜已经完成的录制器准备不因辅助记录或剩余暂存文件删除失败而被误报为更新失败。** 仅在完成事实、文件归属及必要检查已确认时告警保留残留；不能把记录损坏、未知归属或未完成的正式包当作可用。诊断应区分更新记录异常和启用选择异常，并保留最先发生的失败。
- **EXP-32｜取消一次录制准备只结束该请求，不影响另一独立的后台准备。** 应用退出会取消全部准备并等待清理结束；失败后可在同一应用进程重新尝试，不要求重启或清空用户目录。
