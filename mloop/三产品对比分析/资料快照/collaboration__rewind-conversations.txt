回退最近对话（Rewind）

Rewind 是 Loop 里专门用来回退某个会话面最近一段对话的动作。

最稳妥的理解方式是：它不是“万能撤销”，而是把某条消息及其之后的那段 suffix 从当前会话面里一起删掉，让会话面回到那条消息发送前的状态。

它适合用来做什么

Rewind 更适合这些场景：

你刚发出一条自己后悔的消息，希望把它和后续由它引出的最近一段对话一起回退
某条最近的人机往返已经明显走偏，希望把这段 suffix 收掉，重新开始
你想恢复最近的会话面，而不是只补一条“更正说明”
它作用在哪些地方

当前用户可以把 rewind 理解成覆盖这些会话面：

频道主线
回复话题
DM 主线

也就是说，它不是只对某一种聊天视图有效。

它稳定保证什么

Loop 对 rewind 的稳定保证是：

目标消息及其之后的那段对话会从会话面里被删除
当前 conversation state 会回到那条消息发送前

这是用户最该依赖的产品语义。

它不保证什么

Rewind 不应被理解成“把世界恢复到当时的一切状态”。

当前用户最应该记住的边界是：

代码改动是否恢复，取决于具体 runtime
本地 workspace 文件是否恢复，取决于具体 runtime
memory 是否一起恢复，取决于具体 runtime
外部副作用是否回滚，也取决于具体 runtime

所以 rewind 更像“回退会话面”，而不是“一键回到过去”。

什么时候更适合用 rewind

更适合用 rewind 的信号通常是：

这段对话还很新
主要是你自己刚发起的这条线索出了问题
还没有其他人基于它继续建立更多有效上下文

如果团队已经围绕这段内容继续展开，很多时候更适合：

在话题中补充澄清
直接新开一条正确的跟进
把需要继续追踪的事项落成任务
常见阻止原因
不是你自己发的目标 human message

当前 rewind 不是用来删除别人消息的。

更准确地说，它要求目标消息必须是你自己发送的 human message。

后面已经有其他 human 继续说话

如果 suffix 里已经包含其他 human 的消息，rewind 会被阻止。

这条规则的核心语义很简单：别人已经在这条线上继续参与了，系统不会默默把别人的后续内容一起删掉。

这条线已经不是最近的热对话

如果目标消息已经不在适合 rewind 的近期范围里，rewind 也会失败。

可以把它理解成：rewind 是针对最近、仍然热着的那段对话的产品动作，不是一个长期历史编辑器。

相关 agent 不满足 rewind 条件

有些 rewind 会因为相关 agent 的运行条件不满足而失败，例如：

当前 runtime 不支持 rewind
必要 recovery point 缺失
这段 agent 活动已经跨到别的会话面
对应 agent 或 machine 已经不可用

从用户角度，不需要记住所有内部术语，但需要知道一件事：agent 参与过的对话能不能 rewind，不只取决于消息本身，还取决于运行恢复条件。

这段对话里已经分叉出回复话题

如果你想回退的那段主线中间已经分叉出了回复话题，系统有时会要求你先从更靠后的分叉开始处理。

可以把这理解成：rewind 只能沿着一条清晰的最近线索往回退，不会在中间留下断裂分叉。

一个简单判断方法

当你犹豫该不该用 rewind 时，可以先问自己：

我想回退的是最近这段会话面，而不是所有外部副作用吗？
目标消息是不是我自己刚发的那条线索？
这段内容后面有没有其他 human 已经继续参与？
我是真的要收掉这段 suffix，而不是只想补一句澄清？

如果大部分答案都是“是”，rewind 就更像合适动作。

常见误解
误解一：rewind 等于撤销所有后果

不是。

它稳定回退的是会话面，不是所有文件、memory 和外部系统状态。

误解二：只要我是管理员，就能替别人 rewind

不应该这样理解。

当前产品语义强调的是“回退自己刚发起的那段 human suffix”，不是管理员替所有人编辑历史。

误解三：rewind 适合处理很久以前的历史

不是。

它更适合处理最近、仍然热着、没有被大量后续协作覆盖的那段对话。
