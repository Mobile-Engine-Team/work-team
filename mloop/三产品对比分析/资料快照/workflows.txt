工作流

工作流把可重复的过程保存成由动作和控制步骤组成的图。遇到条件判断、审批、等待、循环、并行分支，或多个相互依赖的智能体动作时，工作流比“定时发送一条消息”更合适。

如果当前组织尚未开通工作流，工作区一级侧栏和快捷创建菜单均不显示工作流入口。 直接访问工作流链接会回到工作区收件箱，且不会加载工作流定义或运行记录。

先理解三个概念
工作流：可复用的流程定义，以及它要求的输入。
定时任务：按指定时间启动某个工作流的一份已保存配置。
运行：某个已发布工作流版本的一次实际执行。

协作区域里的定时消息和工作流定时任务不是同一个功能：前者是在将来发送一条已保存的消息，后者会启动一个已发布的多步骤工作流。

工作流页面导航

从工作区一级入口打开 工作流，可进入模块下的三个入口：工作流、 定时任务 和 运行记录。访问模块根路径（/work/workflow）会落到 定时任务。

定时任务 回答“什么时候跑”：三天日历按日期展示昨天、今天和明天，把已经接受的 运行和即将发生的定时任务按时间顺序放在一起；类型筛选可在“全部 / 定时任务 / 运行记录”之间切换。日历右侧的状态条展示同一时间段的运行结果，其下按时间倒序列出 该时间段内的运行记录。定时任务本身的配置（触发方式、输入、是否启用）在它所属的 工作流详情里管理。

三个页面都默认进入“我的”：列出你创建的工作流、你拥有或创建的定时任务，以及你或 你的智能体启动的运行；切换到 “工作空间” 才查看全量。选择会写入 URL，刷新和在页面间 切换后保持，删除该参数则回到“我的”；“我的” 请求失败时页面显示错误和 重试， 不会展示成正常空集合。也可以按 3 天查看过去或未来时间段并随时回到今天；点击显示的 日期范围可从月历选择任意三天时间段的中间一天。运行时间较长的记录使用有上限的分档 高度并显示持续时间，不会按实际时长无限拉高。

让智能体编写工作流

明确告诉智能体你希望设计、创建、修改或运行工作流。创建或实质修改前，智能体会在 对话中展示完整流程图、各 Agent 节点的完整任务 Prompt，以及输入输出、审批、返工和 结束条件，等你确认后再执行获授权的操作。需要调整时继续在原对话中说明即可。

创建草稿、发布、运行和设置定时触发是分别授权的操作。你可以明确授权免再次等待确认； 智能体仍会展示完整内容，并保持你授权的操作范围。

创建和编辑工作流

打开 工作流 后选择 新建工作流，或在空列表里点一个起步模板。编辑器会以该模板打开，在你保存之前不会创建任何东西，直接离开不留痕迹。可视化画布和 YAML 编辑的是同一份草稿；需要由 Loop 持续整理节点位置时可以打开 自动布局，开启期间节点位置由系统管理。关闭后会保留当前位置，并允许手动拖动节点。确认草稿可运行后点击 保存；Loop 会先校验，再创建供后续运行使用的保存版本。校验或保存没有通过时会弹窗列出问题，同时这些问题仍然标在画布上各自的步骤里。

点击 添加步骤 后，可以按“下一步要做什么”选择与 Loop 现有能力对应的步骤；添加后会自动选中、居中并打开核心配置，同时预填一个友好的画布名称。从尚未连接输出的步骤添加下一步时，Loop 会自动创建第一个有效连接；遇到分支步骤需要连接多条路径时，再使用画布补齐其他路径。创建任务 步骤会在频道或话题的看板上创建一个未指派任务：你可以选择看板、填写标题，并按需补充描述；投递重试是平台固定策略，该步骤不提供重试配置；该步骤没有指派、认领、状态或父子任务配置，创建后也不会再修改任务。它的输出包含新任务的身份、编号、范围和看板范围，后续步骤可以选择 output.taskScope 作为发送目标，或在文案里引用 output.taskNumber。如果看板无法解析，或本次运行的发起人没有在该看板创建任务的权限，步骤会以明确原因失败，而不会改到其他看板创建。旁边的步骤查找器可以按名称、ID 或类型选中并居中已有步骤。悬停或选中符合条件的普通连接时，可以直接插入消息或等待步骤；如果插入可能改变数据、审批决定或控制流，Loop 会隐藏这个快捷入口，改由画布或 AI 编辑处理。 选中尚未连接输出的步骤时，右侧面板会说明如何添加下一步，并提示从当前步骤的输出端口拖动连接。

当消息步骤要发送“标题 + 来自消息输入的正文”时，可以把正文写成消息模板（YAML 中的 message:）。它沿用与文本相同的 {{ ... }} 变量，但消息变量会在原位置展开，并保留其中的图片、文件、Markdown 和换行。检查器里的“保留消息变量中的附件”开关会把同一段文字切换成这种形式；纯文本仍会把消息变量渲染成 JSON，并丢失其中的文件。

右侧面板依次提供工作流信息、当前选中的步骤或连接，以及 AI 编辑。工作流 页里的输入参数、输出结果和状态变量可以就地增删改：点分组右上角的铅笔进入编辑，加字段、选类型、填显示名后点勾保存；这些字段就是各步骤能引用到的数据。选中普通步骤后，可以点击 编辑，用与字段类型匹配的控件修改配置。表单先显示这个步骤的核心配置，再显示画布名称和输入。点击 应用 只会更新当前本地草稿，确认后还需要点击 保存 才会持久化。这次修改本身没有引入新问题时就能应用，流程里其他还没做完的地方不会拦住这一步；正在编辑的步骤在画布上会直接显示你填的内容，并标出尚未保存。分支步骤的条件用选择的方式填写：先选看哪个数据，再选怎么比，最后填跟什么比；需要「并且」「或者」把多个条件组合起来时，交给 用 AI 编辑。会影响分支、端口或连接关系的字段保持只读，并提供 用 AI 编辑。可选或条件字段会在需要时出现，但已有的旧值或无效值不会被隐藏，以便修复。协议固定值保留在步骤摘要中，不再显示成不可操作的表单字段。如果表单里还有未应用的修改，离开前会先询问是否放弃；应用后尚未保存的草稿则可以选择 保存并离开 或 不保存并离开。 可以使用画布工具栏中的 撤销 和 重做，或按 ⌘/Ctrl+Z、⌘/Ctrl+Shift+Z 在最近的本地画布修改之间前进后退。平移画布不会占用撤销步骤，输入框仍保留浏览器原生撤销。

第一次进入工作流时，Loop 会打开一次助手选择窗口。你可以选择一个自己的智能体，也可以直接关闭；系统会记住这次选择，之后不会再次打扰。保存选择后，桌面标题栏里的助手按钮会提示一下，之后可以在那里更换助手。

配置问题会显示在相关节点或连接上，并在右侧检查器中靠近需要处理的配置显示；提示会直接说明下一步怎么改。底部诊断区用于查看完整列表，不再只显示问题总数。

审批步骤提供可选的审批材料配置。新的 approval_details 使用精简的 message（text 与有序 attachmentIds），并可附带现有的 reviewContexts 与由运行时绑定的 reference；不要填写 reference.runId、 stepId、artifactId 或 business* 身份字段。作为 Plan 输入时，审批材料暂不支持 附件；Agent 回调输出可使用当前 Run 已预留的附件。未知字段或未授权附件 ID 会在 Step complete 时 返回可修正的字段错误，不会先记录完成再使后续 Run 卡住。 已发布的工作流继续按旧 envelope 兼容。智能体提交材料时 Loop 会在创建审批前校验； 失效的 Review Card 导航提示会降级丢弃，不会隐藏正文。关闭此配置会移除 requestApproval.details，材料与简短摘要保持独立。

画布工具栏会把 自动运行 和 运行 分开显示。工作流本身只是定义；只有创建并启用定时任务后，才会自动运行。状态会明确区分未配置、已关闭和已开启，右侧工作流信息面板会提供当前适用的创建或管理入口。

修改跨越多个节点，或更适合用语言描述时，可以选择 AI 编辑：

选择一个自己拥有的智能体。
用日常语言说明修改要求，也可以插入常用指令并替换其中的占位内容。
如有需要，在画布中选择节点或连接，把它作为本次消息的上下文。
发送请求。

输入框中的文字和它关联的画布对象会作为一个整体保留。输入框不为空时，选择其他节点不会偷偷替换编辑对象；明确发起切换后，可以选择保留当前对象或改用所选节点。主动清除附件后会回到整个工作流的上下文。附加的画布元素用于帮助智能体理解要求，并不限制智能体只能修改那一个位置。

请求发出后，可以直接切到任务、频道等页面，智能体会继续编辑，不会仅因智能体正在工作或草稿尚未发布而弹出离开确认。返回工作流后会恢复编辑状态和最新草稿。只有尚未保存到服务端的手工修改仍会触发防丢失提示。

当一次智能体请求可以明确归因到一版草稿修改时，同一面板会显示 AI 已更新草稿。可以在原有画布中查看标出的节点，以及归组后的配置或布局变化。点击 完成检查 会保留已经更新的草稿；如果期间没有其他人继续更新草稿，也可以点击 撤销这次修改 恢复请求前已经保存的内容。此次对比和一键撤销在同一工作区会话内切换页面后仍会保留；如果离开期间草稿又有更新，返回时会移除过期对比和撤销入口；刷新页面或换设备后不会重建此次对比，但已经保存的草稿不会丢失。

如果智能体完成后没有修改已保存的草稿，同一面板会直接说明草稿没有变化，不会进入修改检查；你可以继续在原输入框中调整要求并再次发送。

查看发布记录

点击工作流描述后的最新发布信息，可以查看最近 5 个版本。点击其中一个版本会直接打开对应快照；点击 查看全部发布记录 会打开完整记录并选中最新版本。所选版本会以只读方式显示在原有的可视化画布或 YAML 视图中，右侧面板则列出所有已发布版本；最新发布和默认运行是两个独立状态。

点击版本行即可在原位置预览。符合条件的版本可以通过行尾菜单设为默认运行版本，或基于该版本重新发布。更改默认运行版本只影响之后未指定版本的运行，不会改变已有定时任务和已经开始的运行。重新发布会创建新的不可变版本，不会修改当前草稿、之前的版本或已有定时任务。

点击 返回当前草稿 或按 Esc 可退出只读预览。打开发布记录前的草稿修改、画布位置和选择都会保留。

Inbox 汇总入口

隐藏 Inbox 中的 Workflow 汇总入口不会删除运行。后续有新的运行活动时，入口会重新出现；恢复后置顶或取消置顶不会再次隐藏它。若再次主动隐藏，则需等待更新的活动才会恢复。Task 汇总入口遵循相同规则。

立即运行

同一次运行中的图文输入可以同时用于多个发送消息或创建任务步骤，无需重新上传图片。各处保留独立的附件归属，图片顺序和 GIF 动画保持不变；步骤重试不会重复创建附件。

消息步骤的 selectOne 随机策略也支持只配置一个 Agent；重复候选去重后只剩一个也可以。该 Agent 忙时仍按正常规则等待，不会绕过权限或同时承接多份流程工作；候选名单不能为空。

在工作流详情中选择 运行，会启动默认的已发布版本。右侧紧凑菜单提供 添加定时任务 和 管理定时任务 两个入口。主按钮始终是立即运行，不会因为使用菜单而改变。Loop 会按照该版本的输入定义生成表单：

有限选项使用选择器；
频道、成员、智能体和协作范围只能从当前工作区可访问的资源中选择；
数字、日期、时长、列表和结构化值使用与声明类型相符的控件。
消息输入使用与频道、话题相同的输入框，可以添加图片或 GIF；图片按当前光标位置插入正文，保持“文字 → 图片 → 文字”的顺序，正文中的 attachment:// 引用决定最终排版，附件集合只认领仍被正文引用的文件；Enter 换行，只有显式提交（⌘/Ctrl+Enter 或 运行）才会启动，正文与活跃附件至少有一项非空。

选择 展开工作流预览 可以查看画布。鼠标悬浮或键盘聚焦某个输入时，使用该输入的节点会变得更明显。校验或启动失败后，弹窗会保留已经填写的内容，包括正文和附件，方便直接修改并重试；启动结果未知时沿用同一次启动标识，刷新同一标签页后仍可继续。

创建定时任务

在工作流详情中打开 定时任务，选择 新建定时任务，当前工作流会自动预选。也可以从主 定时任务 列表选择 新建。列表默认进入“我的”并保持你选择的范围，切到 “工作空间” 可以看到全部定时任务。Loop 会自动使用工作流的最新发布版本；设置执行时间后，再补充该工作流要求的输入。完成的配置区会折叠成摘要，但仍可随时重新编辑。修改前面的内容时，只有受影响的配置区会失效或需要重新确认。

如果当前没有可运行的已发布工作流，工作流选择器仍可打开，并提供返回工作流列表的入口，而不是显示成无法操作的控件。

查看运行记录

主 运行记录 列表按本地自然日分组，并将最新日期排在前面，默认进入“我的”并保持你选择的范围，他人启动的运行需要切到 “工作空间” 才能看到。展开或折叠某一天后，点击运行记录的任意位置即可进入详情。每行依次展示启动时间、工作流名称、可用的运行耗时、来源和状态。状态只通过最前面的图标展示一次；手动与定时任务来源 Badge 使用不同图标。

运行记录提供两种主要视图：

运行图：查看已执行节点、状态、尝试次数和分支信息。
YAML：查看本次运行固定使用的工作流源文件。

带 callback 的步骤会在运行图和执行详情中单独显示 Recovery 状态。等待中的 callback 显示“等待 callback”或“Recovery 第 n / 10 次”，以及最近结果和下次 Recovery 时间。自动 Recovery 按 1/2/4/8/16 分钟退避，后续每次固定 30 分钟；第 10 次位于初始锚点后 181 分钟。offline 或 runtime/Hub 身份未知时，到期仍使用同一持久化 Recovery delivery 路径。已完成、失败、取消或耗尽的 callback 会显示终态；耗尽会明确显示 10 次尝试后 Recovery 已耗尽，并隐藏下次 Recovery。Recovery 元数据缺失或未知时显示“Recovery 详情不可用”，不会猜测状态。

运行图会跟随当前步骤：首次加载以及切换到另一个运行中的步骤时，该步骤会在视图中居中。首次聚焦使用默认缩放；之后切换步骤会保留你正在使用的缩放，只在步骤显示不下时缩小到刚好完整显示，你手动调整过的视图会一直保留到焦点步骤变化为止。发出消息、请求审批或创建任务的步骤会链接到它们各自的目标——原始消息、该次执行创建的审批卡片，或该步骤创建的任务。收件箱时间线中的活动行使用同一套关联规则，因此某一步骤中每个可导航的活动都打开该步骤的目标。没有唯一已提交目标的步骤保持纯文本，不会变成可点击内容。目标是 Task 时，点击会先打开任务页，再加载详情，不必留在工作流页面等待任务内容。

将鼠标移到可点击的图节点上，或用键盘聚焦它的链接时，整张卡片会轻微放大，移出或失去焦点后平滑恢复，画布布局保持不变。系统启用“减少动态效果”时保留背景和阴影反馈，但不缩放或播放过渡动画。

工作流、定时任务和运行记录详情的 Header 左侧都提供返回所属列表的按钮；从日历打开的运行记录则返回定时任务页。

通过 更多操作 → 调试数据 查看运行的原始输入、当前状态、输出、错误和 callback recovery 数据。对于仍在进行的运行，取消运行 位于同一菜单的最后一项，执行前会要求确认。

详情面板会关联到对应的工作流；如果本次运行来自定时任务，也会显示对应来源。运行仍在进行时，页面会自动刷新；短暂刷新失败不会清空当前内容。

使用建议
在工作流输入定义中提供用户容易理解的名称和说明。
不允许自由输入时，应声明为选项、频道、成员、智能体或协作范围类型。
可执行逻辑变化应发布为新版本；已经开始的运行仍固定使用原版本。
启用定时任务前，先用 运行 检查重要分支。
收件箱中的工作流运行

新建工作流默认关注后续运行。工作流上的开关只影响此后接受的运行，不会改变已有运行，也不会改变其他成员的选择。

在收件箱中选择 工作流，打开运行即可查看只读活动时间线。该页面没有消息输入框，只展示已批准且有界的公开活动事实，不会复制运行输入、编译器内部步骤或任意错误内容。连续线性进度可以分组展示，分支、循环、等待和审批保持独立。

打开运行时会先加载最新一页活动。与普通消息一样，在前台查看期间，系统会自动标读到已加载的最新活动，不需要逐条滚动查看；更早的活动仍可翻页阅读。切到后台或离开该运行后停止自动标读，尚未加载的新活动和其他运行的未读不受影响。

关注和取消关注只影响你在当前运行中的成员关系。重新关注以当前活动位置为起点，不会把历史活动补成未读。如果你有权更新工作流，关闭当前及后续通知会在同一事务中取消你对当前运行的关注，并关闭该工作流对未来运行的默认关注。使用同一请求安全重试不会修改其他已有运行或其他成员的关注状态。
