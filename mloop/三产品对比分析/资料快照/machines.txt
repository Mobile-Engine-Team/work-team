机器

机器是 Loop 把本地执行环境接入工作区的方式。

没有机器，Loop 只能承载协作；有了机器，智能体才能真正运行在你的本地环境里。

机器在 Loop 中承担什么角色

接入机器之后，Loop 才能：

判断一台机器是否在线
承载智能体的当前运行
使用本地运行环境
使用本地工作区和文件

因此，机器既不是普通配置项，也不是纯展示对象。它是 Loop 客户端与实际执行环境之间的连接点。

查看和管理机器

机器页面默认展示你自己管理的机器和智能体。即使你是工作区管理员，也不会在默认页面自动看到所有人的机器。

工作区管理员可以从机器页面的设置按钮进入机器管理页面。这个管理页面会展示工作区内的所有机器，并提供驱逐入口。

机器管理页面会按页加载主机，滚动到列表末尾时自动加载下一页。页面顶部显示主机总数和当前已加载数量。主机按管理它的人员聚合，最前面是「未分配主机」分组，每个分组都可以折叠。主机行显示可选的更新提示、在线或离线状态小圆点和接入时间；过滤栏可以按在线状态或是否有更新筛选当前已加载的主机。页面不会在后台定时刷新，需要最新数据时点击 Header 中的刷新按钮。

机器、daemon 和智能体分别是什么

这三个对象很容易被混在一起，但它们并不是一回事：

机器：Loop 里的机器对象，表示一台接入工作区的本地执行环境
daemon：本地长期运行的 Loop 客户端进程，负责把这台机器连回 Loop
智能体 / 运行状态：智能体是协作角色，运行状态说明它当前是否在某台机器上运行

如果你先把这三层分清，大多数“到底是哪一层出了问题”都会更容易判断。

最常见的两个命令
loop daemon --server-url <url> --api-key <machineApiKey>
loop daemon


它们的职责分别是：

loop daemon --server-url ... --api-key ...：把机器接入某个 Loop 工作区；必要时也会顺带启动 daemon
loop daemon：使用本地已保存的连接配置启动 daemon
这一章包含什么
运行与维护 Loop 客户端 解释首次连接、长期运行、重连、版本提示和服务化运行。
管理 Loop 连接 解释本地保存的 Loop 连接如何启用、停用和清理。
机器排障 解释机器离线、智能体不工作、本地运行环境不可用或 daemon 版本提示出现时该先看什么。
推荐的使用方式
第一次接入时，优先使用 Web 页面生成的连接命令
长期使用时，把 daemon 作为常驻进程运行
出现智能体问题时，优先先看机器在线状态
如果页面提示 daemon 版本过旧，先把它当成一方 Loop 版本提醒，而不是外部包市场提示
团队内为机器建立明确命名和用途，方便定位
